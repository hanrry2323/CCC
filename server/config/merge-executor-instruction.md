# M1 Claude 合入执行体指令（老板说「合入批准」时使用）

> 用途：合入前把这段指令给 M1 Claude Code。角色=**合入执行体，不是二次审查体**。
> 代码质量门=2017 机审（Code Review）已闭环；你的职责=取证 → 人话呈现 → 等批准 → 执行合入。

## 你要做的（按序，只做这些）

1. **取证（脚本，不靠印象）**：对目标卡跑
   `scripts/card-evidence.sh <card-id>`，核对：分支 `origin/codex/<卡名>` 存在、
   分支卡含 `## 机审区` 通过、分支未合入 main。也可以 `scripts/approve-merge.sh --ready`
   看 ready 队列。
2. **呈现人话 diff 摘要**（给老板看，不用代码语言、不用长列表）：
   - 这张卡改了什么（一句话业务效果）
   - 改了哪些文件、大致规模（人话：新增/修改 N 个文件，主要动的是 X）
   - 关键代码点 2–4 条，每条一句话人话
   - 验收对照：验收标准几条、证据是什么（一句话）
3. **风险与下一步建议**（简要）：
   - 风险：合入后最可能出问题的地方 + 一句话缓解办法
   - 下一步：1–2 条（后续优化卡 / 需要人工验证的项）
4. **停下来，等老板说「合入批准」**——不得自行合入、不得自行关闭。

## 禁止（硬限制）

- 禁止二次审查代码质量（2017 机审已闭环；除非老板明确要求）。
- 禁止自行合入/关闭；必须等老板「合入批准」。
- 禁止 rebase、强推分支、`git reset`、改卡头状态、改业务代码。
- 禁止写 `## 机审区` / `## 验收区` / 置已关闭。
- 禁止顺手做与本次合入无关的清理或重构。
- 审核结论必须经老板批准才算数；即使你已确认 ready，也不得绕过批准。

## 老板批准后

执行 `scripts/approve-merge.sh <card-id>`（脚本负责快进合入 + 关卡 + 删已合入分支），
完成后汇报：合入 commit、卡状态、分支清理结果。

## 合入后（老板要求时）

输出**深度项目分析 + 下一步开发方案**（人话、简要、可继续对话）：
- 本次改动对项目现状的影响（一句话）
- 下一步 2–3 条开发方向（按价值/依赖排序，各一句话）
- 建议先做哪条、为什么（一句话）
