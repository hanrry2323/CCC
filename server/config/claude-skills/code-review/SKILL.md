# Code Review（合入前强制审查）

## 定位

合入批准前的最后一道质量门。审查执行体回写的分支信封（工作 + 卡），
发现的问题**就地修复并复审**，闭环后才允许「合入批准」。

## 审查清单（逐项取证，全部通过才可判「通过」）

1. **正确性**：逻辑 / 边界 / 空值 / 竞态 / 异常 / 资源泄漏 / 死代码。
2. **契约一致性**：前后端 / 接口 / 卡头验收标准是否一致。
3. **健壮性**：超时 / 重试 / 降级 / 错误提示 / 轮询。
4. **范围与红线**：只改卡内白名单；无密钥 / 无关仓 / 大删；未直推 main；
   未写 `## 验收区` / 未置已关闭。
5. **验收标准**：逐条对照卡 `## 验收标准`，附可验证证据（命令 / 输出 / 文件）。
6. **老板批注**：若卡含 `## 人工批注`（最高开发指令），核对 `## 批注落实`
   说明与代码实证，未落实 → 不通过。

## 发现分级

- **P0**：阻断合入（安全 / 数据 / 核心逻辑错误）。
- **P1**：应修（明显缺陷 / 契约不符 / 验收未达）。
- **P2**：建议（非阻断，记录进机审区）。

## 处理规则（就地修复闭环）

1. P0/P1 → 在 worktree 分支**就地修复** → `commit + push`
   （提交信息引用发现编号，如 `fix(review): P1-2 …`）→ 按清单**复审修复 diff**。
2. 修复只动问题相关代码，禁止顺手改无关内容、禁止扩大范围。
3. 连续 2 轮修复仍未闭环 → `机审：不通过`（原因清单），触发打回 / 修订流程。
4. 范围性 / 架构性问题（就地修不了）→ `机审：不通过`（原因 + 建议），
   触发打回 / 修订流程。
5. P2 → 记录进机审区，不阻断合入（可挂后续优化）。

## 输出格式（写入 `## 机审区`）

```text
机审：通过 / 机审：不通过
- 审查摘要：审查范围、分支 tip、涉及文件
- 发现清单：编号 / 级别 / 文件 / 问题
- 修复记录：发现 → 修复 commit（P0/P1 必填）
- 复审结论：按清单复核结果
```
