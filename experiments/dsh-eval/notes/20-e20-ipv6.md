# 实验 E20 · headless IPv6 残余

- **状态**：✅ 完成（实验路径已覆盖）
- **批次**：B5 多代理
- **环境**：配置 + 实测
- **日期**：2026-08-16

## 结论

**实验 runner 已带 IPv6 防护（`NODE_OPTIONS=--dns-result-order=ipv4first`），headless 实验路径不受影响**。但该 flag 只存在于 web plist 和实验 runner；**任何不经 runner 的 DSH 进程仍缺**——残余风险是「临时手动起 DSH」而非本实验路径。

## 证据

- 报告维度七：「opencode.ai 有 AAAA 而本机无 IPv6 路由，node 默认 IPv6 优先 → 每请求 25s TCP 握手超时；已修（NODE_OPTIONS=ipv4first）但仅 web plist 有」
- 实验 runner（run-headless-code.sh）显式 export `NODE_OPTIONS=--dns-result-order=ipv4first`（B0 环境笔记已述）
- 本次全部 headless 实验（B0-B5）未遇 IPv6 超时，均正常完成

## 结论细节

- 实验路径 100% 覆盖；残余风险仅限「不用 runner 的手动 DSH 调用」。
- 根治方案：把 flag 写进 headless profile 或系统级，而非依赖调用方传。

## 风险 / 对 CCC 借鉴的影响

- 部署注意点：DSH 的 IPv6 flag 是「进程级 env」不是 profile 配置——CCC 若用 DSH 执行体，启动脚本必须带此 flag。
