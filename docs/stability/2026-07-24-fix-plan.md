## 1. 第一批：红线 12 实质化 + Engine 不自杀（堵漏，< 1 day）

**目标**：把"agent 不要主动 set_mode enabled"的约定提升为机制；让 Engine 不再自杀；Hub exit 不留孤儿子进程；LAN 暴露面收窄。

### 1.1 `_ccc_control._write_raw` 加 fsync + tempfile.mkstemp + flock

- **文件**：`scripts/_ccc_control.py:60-66`
- **现状**：固定 `.tmp` 名 + 缺 fsync；CLI 与 Hub 写者无共享锁
- **改动**：
  - 临时文件改 `tempfile.mkstemp(dir=CONTROL_DIR, prefix=".control-", suffix=".tmp")`
  - 加 `os.fsync(fd)` 后 `os.close(fd)` 再 `os.replace`
  - 加 `fcntl.flock(LOCK_EX | LOCK_NB)` 包整个 read-modify-write
- **验收**：`scripts/tests/test_ccc_control.py` 加并发写测试；`bash scripts/ccc-self-check.sh` 仍绿
- **commit**：`fix(control): _write_raw 加 fsync + flock，堵并发写覆盖`

### 1.2 `set_mode` source 白名单

- **文件**：`scripts/_ccc_control.py:134-211`
- **现状**：`set_mode("enabled", source=任意字符串)` 都接受；`source` 仅元数据不参与策略
- **改动**：
  - 定义 `_ALLOWED_SOURCES = frozenset({"cli", "task_dispatch", "daily_review", "ops_manual"})`
  - `set_mode` 接受 source 不在白名单时 `raise ValueError`
  - 默认 source 改为必填（无 source 不接受）
- **验收**：现有 `scripts/tests/test_ccc_control.py:26-96` 需加 source 白名单用例
- **commit**：`fix(control): set_mode source 白名单，红线 12 实质化`

### 1.3 watchdog 先 flush 再硬退

- **文件**：`scripts/ccc-engine.py:456-493`
- **现状**：tick 超 180s 直接 `os._exit(0)`，跳过 finally/atexit/持久化
- **改动**：
  - watchdog 触发硬退前先 `flush_active_tasks_to_disk()` + `events.append("engine_hard_exit")` + `os.fsync` events
  - 设 `_WATCHDOG_HARD_EXIT_GRACE_SEC = 10`，watchdog 触发后 10s 内若主循环恢复则取消硬退
  - testing gate 默认 180s 预算在 `gates.py:620-634` 改为 240s + 软提醒
- **验收**：构造 5s 长 tick，watchdog 不应误杀
- **commit**：`fix(engine): watchdog 先 flush 再硬退，避免自杀丢状态`

### 1.4 graceful shutdown 阶段化（杀子进程组）

- **文件**：`scripts/ccc-engine.py:4400-4444`
- **现状**：shutdown 只设布尔标志，main 终止不杀子进程
- **改动**：
  - shutdown 阶段化：
    1. 停 intake（不再 accept new tasks）
    2. 持久化所有 in-memory 队列（`pending_relaunch / product_inflight / relaunch_meta`）
    3. 遍历 `active_tasks` 给每个 runner PID `SIGTERM` + 等 5s + `SIGKILL` 兜底
    4. 释放所有 slot
    5. `events.append("engine_graceful_exit")` + fsync
  - 复用 `_kill_process_tree`（`ccc-engine.py:3970`）
- **验收**：模拟 SIGTERM，断言无残留 PID 文件
- **commit**：`fix(engine): graceful shutdown 阶段化，杀子进程组不留孤儿`

### 1.5 `_lifespan` 加 `session_manager.shutdown()`

- **文件**：`scripts/chat_server/app.py:49-54`
- **现状**：lifespan 只 `close_client()`，未调 `session_manager.shutdown()`
- **改动**：
  - lifespan 退出前 `await session_manager.shutdown()` 包 try/except
  - `ClaudeSessionManager.shutdown` 实现：遍历 `_slots`，`cli_pids` 给 `SIGTERM` + `asyncio.wait_for(proc.wait(), 5)` + SIGKILL 兜底
- **验收**：FastAPI lifespan 单测覆盖 shutdown
- **commit**：`fix(hub): _lifespan 加 session_manager.shutdown，Hub exit 不漏子进程`

### 1.6 plist 默认 127.0.0.1 + ccc:ccc 升 SystemExit

- **文件**：`scripts/install-hub-plist.sh:68-72, 107-108` + `scripts/chat_server/config.py:17, 272-277`
- **现状**：默认 `CCC_CHAT_HOST=0.0.0.0` + `CCC_CHAT_USER=ccc` + `CCC_CHAT_PASS=ccc`，写在 plist 里
- **改动**：
  - plist 默认改 `CCC_CHAT_HOST=127.0.0.1`；如需 LAN 暴露要求显式传 `CCC_CHAT_HOST=0.0.0.0`
  - `validate_auth_config` 把 `AUTH_PASS == "ccc"` 升 `SystemExit`（已警告但放行）
  - `AUTH_USER == "ccc" and AUTH_PASS == "ccc" and HOST == "0.0.0.0"` 组合直接拒绝
- **验收**：跑 `bash scripts/install-hub-plist.sh` 在默认配置下应 SystemExit；显式 `CCC_CHAT_HOST=0.0.0.0` + 自定义口令可启动
- **commit**：`fix(hub): plist 默认 127.0.0.1 + ccc:ccc SystemExit，收紧 LAN 攻击面`

## 2. 第二批：原子化（1-2 week）

**目标**：所有写路径 fsync + journal + 单一事务；杜绝"概率性正确"。

### 2.1 `active_tasks` 走 `_atomic_write` + flock + 备份校验

- **文件**：`scripts/engine/active_tasks.py:78-104, 107-172, 175-211`
- **现状**：直接 `write_text`，崩溃可截断；加载 JSON 失败即 `{}`，**重复 launch/超卖**
- **改动**：
  - 复用 `scripts/_atomic_write`（如有）或新建 `_atomic_write_json`
  - 加 `fcntl.flock` 包整个 write
  - 加载 JSON 失败时备份原文件 `.bak` 再 `{}` 而非直接重置
  - `ps` 超时/失败保守保留并逐个 `kill(0)` 二次核验；捕 `TimeoutExpired`
- **验收**：kill -9 中断 write 路径后恢复测试
- **commit**：`fix(engine): active_tasks 走 atomic_write+flock+backup`

### 2.2 board move + index 单一事务

- **文件**：`scripts/_board_store.py:872-976, 1013-1032, 1211-1262`
- **现状**：move 先原子生成目标再 unlink 源；index 不是每个 move 自动更新；state.md 在 board lock 外单独写
- **改动**：
  - 引入 journal/WAL：intent → 写目标 → fsync 目标目录 → 删源 → fsync 源目录 → commit
  - index 改为读时按 generation 派生，或 move 事务内强制更新
  - state.md 用同一 lock 范围
- **验收**：多进程故障注入测试（持锁期间第二写者必须超时且无磁盘变化；move 各阶段 kill 后 repair 恰有一个 canonical 副本）
- **commit**：`fix(board): move + index 单一事务，加 journal`

### 2.3 `pid_file` 用 `O_CREAT|O_EXCL` 先占位

- **文件**：`scripts/opencode-exec.py:211-215`、`scripts/board/roles/dev.py:397-414`、`scripts/board/roles/product.py:553-562`
- **现状**：Popen 后写 pid，窗口期竞态（Lesson 44 已踩）
- **改动**：
  - 启动前先 `os.open(pid_file, O_CREAT|O_EXCL|O_WRONLY)` 占位
  - `try: pid_file.write_text(f"{pid}\n{started_at}\n")` 写入实际 PID
  - 失败清理占位文件
- **验收**：concurrent launch 同一 workspace 不会有双 pid 文件
- **commit**：`fix(executor): pid_file O_CREAT|O_EXCL 先占位，堵窗口期竞态`

### 2.4 `remember_last_epic` / `_remember_client_request` 走 tempfile + fsync + replace

- **文件**：`scripts/chat_server/services/flow_events.py:457-466, 469-480, 541`
- **现状**：`path.write_text()` truncate-write 无 fsync
- **改动**：复用 `session_store._atomic_write_text` 同模式（tempfile + fsync + replace）
- **commit**：`fix(flow): remember_last_epic atomic_write，与 session_store 一致`
