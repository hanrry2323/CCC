03

核心决策 D1–D10

永久基线 · 冲突时以此为准
D1

架构重构

薄驱动 Engine + 文档流转 + 看板/HTTP；砍掉角色分层、三档契约、能力包、重试预算等重型机制。

D2

绝对独立 红线

CCC 与 QXMAP 运行时零依赖：不读、不查、不写外脑；采集/任务/知识全部自建；违反即漂移。

D3

CCC 的脑

自建知识库，接 MCP、读全库、做到最强；最强用在拆方案/验收/裁决，执行层保持轻。

D4

定时任务

由 Engine 承担：到点发单 → 派发 → 收单回写；巡检默认只读，变更类保留确认。

D5

看板 = 总调度台

任务流转（实时/7 天/项目分类）+ 线路图（派生视图，人只点确认可用）+ 集群状态 + 运维页。

D6

验收层

安全三件套 + 基础编译测试；深度验收归验收 Agent（接知识库），失败打回附问题清单。

D7

管理方式

QXMAP 对话（Codex）管理；Trae 积分期过渡执行；后期主力 OpenCode + Claude Code；Codex 验收。

D8

外脑治理

决策强制影响声明；旧记录标废弃不删；模糊标待核由老板裁决；机器校验 + 人确认。

D9

中转站并入

ai-loop-router 作为 CCC 基建配属，随服务端部署在 2017；调用方切换后再停 M1 旧实例。

D10

杜绝硬编码 永久纪律

工具/路径/地址/端口/模型/密钥全部配置化；任务逻辑全在任务卡文档；验收含硬编码扫描。

P1 · 契约

  • 任务卡格式、状态模型、回写协议
  • 看板数据模型、安全三件套、验收 Agent 职责边界
  • 执行体注册表、运行拓扑规则、硬编码扫描项

P2 · 服务端合体 + Engine + 看板

Engine 驱动 + 任务看板（实时 / 7 天 / 项目分类）；含 CCC 自带中转站部署，执行体模型出口切换。

P3 · 线路图

派生视图三层：CCC 总览 → 单项目 → 项目线路图；状态自动聚合，人只做「确认可用」。

P4 · 定时任务 + 集群 / 运维页

定时任务归 Engine；集群状态与运维页采集独立重做。

P5 · 知识移植 → 移交

一次性种子移植（节点/路径/项目元数据/决策/教训）→ CCC 独立运行，外脑回归纯顾问。

06

红线与纪律

永久生效
1

不破独立：CCC 运行时不读不写外脑，违反即漂移。

2

最强脑不抢执行：脑负责拆方案/验收/裁决，不自己下场写码。

3

验收 Agent 不能砍薄：唯一质量兜底，接知识库、能看全上下文。

4

定时任务默认只读：变更类必须走任务卡并保留确认。

5

线路图是派生视图：禁止手工维护，状态自动聚合。

6

旧内容标废弃不删除：删除权在老板。

7

杜绝硬编码：验收含硬编码扫描，发现即打回。

8

多壳必须锁门：对话口账号密码 + 会话 token。

07

风险与缓解

风险缓解
隔离破功（顺手查外脑）契约写死 + 验收检查
线路图漂移状态自动聚合，人只确认
最强脑成本只用在方案 / 验收 / 裁决三处
过渡期 QXMAP 职责过重递减移交，以 M4 为界
停 M1 中转站未切换调用方（Claude Code / OpenCode / Codex）CCC 自带中转站就绪并切换后再停
硬编码回潮验收含硬编码扫描；注册表 / 路径权威表 / 配置化强制
