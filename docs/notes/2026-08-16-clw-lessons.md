## 封板收尾必须扫尾关联卡/方案到终态

**背景**：clw027 卡 2026-08-15 出卡（`23c4e0c5`）后未走产线执行（无派发/无回写），同日老板决策项目封板（`8402a4e5`）。封板只同步了叙述层文档（roadmap / README / 方案正文），未扫尾状态层——clw027 卡停留在「待分派」、clw-plan-006 停留在「部分执行」、registry 仍 `status: active` + `taskable: true`。看板长期显示一张孤儿卡，且 Engine 仍可能给已封板项目派发新卡。

**根因**：封板决策是「叙述落库」不是「状态收敛」。封板时只改了文字描述（「clw027 跑通后封板」），没有把卡片状态机（待分派→已关闭/作废）、方案状态机（部分执行→已完成/作废）、registry 派发开关（taskable→false）一并收敛到终态。叙述与状态脱节。

**标准动作（封板/归档收尾清单）**：

1. 列出项目全部活跃关联卡（待分派/执行中/已回写/打回）→ 逐卡收敛到终态（`已关闭` 或 `作废`，须附原因 + 回写/验收证据）
2. 同步关联方案状态（`已完成`/`作废`），勾选验收清单，更新日期
3. 核对 `registry.yaml`：`status → archived`、`taskable → false`（防 Engine 再派发），notes 记封板决策
4. 全量校验绿（卡 validate + `scripts/validate-plans.sh`）后 commit+push

> 参照先例：cd 项目 2026-08-15 废除（`9f4d34a4`）即按此清单执行；clw 封板同日未做第 1/3 步，本笔记为补收口记录。
