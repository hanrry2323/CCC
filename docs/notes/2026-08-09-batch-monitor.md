## 流程优化建议

### 1. 门禁命令必须适配 worktree 环境（P0）
- 门禁命令不能假设 venv/pytest/项目目录结构存在
- 方案：门禁只做「编译检查」（`cargo check`、`python3 -c "compile(...)"`）和「范围检查」（`git diff --name-only`），不做重体力测试
- 测试交给独立进程（HP 或人工）

### 2. 编译型项目（Rust）的 `cargo test` 不应进开发槽位（P0）
- 首次 `cargo test` 触发全量依赖编译，时间不可控，CPU 打满
- 方案：开发卡只要求 `cargo check`（秒级），测试覆盖率验证移到独立环节

### 3. 机审需要标准化 SOP（P1）
- 当前 prompt 把角色、流程、输出、禁止揉成一段长文
- 方案：机审拆分——轻量门禁检查（脚本） + 原则性审查（LLM，基于项目审查清单）
- 项目审查清单已在阶段 3 建好（`knowledge/domains/projects/<prefix>-review.md`），需注入到机审 prompt

### 4. 确定性门禁失败不应 retry（P1）
- pytest 未安装 → 重试 3 次还是未安装，浪费 3 个执行槽位
- 方案：门禁失败按类型分流——环境缺失（no module/path not found）→ 直接打回，不重试

### 5. 执行体并发槽位不足
- 9 张卡，执行槽位仅 3 个，mx027 占了一个槽位 4 小时
- 方案：卡死检测 + 自动超时 kill（当前已有 timeout 机制，但对编译型任务设置过短会导致误杀，过长则浪费槽位）
