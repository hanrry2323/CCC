## 目标

累计跑完 **300 张开发卡**（业务线 xy/hp/mx + 平台 ccc），达成「当前流程稳定 + 指标基线完整」；
300 卡后用数据排四大升级项（目标驱动闭环 / 自动任务发现 / 技能封装 / 循环健康指标）的优化顺序。

## 范围

1. **继续跑卡不换链**：现有 2017 固定交叉（OpenCode 开发 → Claude Code 机审）与 M1 自验收双轨保持不变。
2. **检查点**：每 50 卡数据快照（只修流程硬伤）；100 卡初排升级项；150–200 卡中期校正；300 卡出下一程优化决策。
3. **埋点看板化**：每卡时长/调用/打回率/机审延迟从 metrics.json 出可视图（`server/web/exec_metrics.py` 数据已就绪）。
4. **参考库补录**：loop-engineering 社区 6 月后资料（Claude 4 循环 / Graph 转向 / SlopCodeBench / Memory Governance）入 HP 参考库。

## 验收

| 指标 | 门槛 |
|------|------|
| 累计跑卡 | ≥300 张（含各业务线） |
| 指标完整 | 每卡 metrics 存在、可汇总（时长/工具调用/模型头） |
| 检查点 | 50/100/150 三次快照留痕，300 卡正式决策档 |

| 新 SOP | 0 |

## 不做

新席位/同义句/AGENTS 长禁令；第二套拆卡 LLM；改 2017 开发-机审固定链路；500 卡目标（除非 150–300 期间数据显著波动再加码）。
