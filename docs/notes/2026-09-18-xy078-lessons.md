# 教训沉淀 · xy078 · 产线失败 fail-closed

## 教训 1：shell 白名单与引擎权威分类器不一致导致 48 轮死复跑

**现象**：xy078 卡连续被 rc=64 拦截 48 轮（run1..run48），代码已写好、6 测试已过、信封已写，但无法传输。

**根因**：`dsh-executor.sh` 与 `pi-remote-executor.sh` 的 A1 批注 fail-closed 闸门硬编码
「无批注」字面白名单（`无|无批注|暂无批注|（无批注。）|无批注。`），不识别 `new-card.sh`
生成的加粗模板占位句「（**老板对打回卡/审核的批注意见写这里…**）」，误判为真实批注 →
强制要求结果信封含「## 批注落实」段 → DSH 正常结果缺该段 → rc=64。

**引擎权威分类器** `server/board/annotation.py` 的 `classify_annotation()` 已收录该模板句
在 `_NONE_ANNOTATION_MARKERS` 白名单，判定为 `NONE`（不需批注落实）——shell 与引擎判定口径不一致。

**根修**（commit `aabc2aba9`）：两处 shell 判定改为 `python3 -c` 调权威 `classify_annotation`，
`_ANN_KIND != "NONE"` 才拦，语义不变。验证：`classify_annotation(xy078卡) = "NONE"` → 放行。

**推广教训**：shell 层不应硬编码与 Python 层并行的判定逻辑——凡有 Python 权威分类器的
字段，shell 一律调 Python 函数，不维护自己的白名单副本。

## 教训 2：卡面协议自相矛盾导致收单死锁

**现象**：xy078 信封已多次成功传输到 `log_dir/xy078-ccc-result.md`（07:09，11100 字节），
但引擎永远看不到——卡状态一直停在「待分派」。

**根因**：卡面回写要求写「卡状态与回写区由引擎收单时代写（A2 契约）」，而
`phase2.consume_once` 的入口条件是「卡已回写」——DSH 完成后卡仍「待分派」，
`list_written_cards` 只从 dispatch 目录和 `origin/codex/*` 分支找「已回写」卡，
两处都不是「已回写」，信封成孤儿，引擎无限重派。

**根修**：手动置「已回写」+ 更新 `~/.ccc/data/cards/cards.index.jsonl` 索引。
引擎立即消费信封并跑 phase2 机审——链路首次完整运转。

**推广教训**：A2 契约（引擎代写卡状态）与 `consume_once`（要求卡已回写才能消费）
两条件互斥。需在设计层面明确：DSH 负责把卡置「已回写」并 push 分支，
引擎负责后续合入与关闭，不应反过来由引擎代写「已回写」状态。
