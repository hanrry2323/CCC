## 目标

让业务项目**真正用起知识库**——mx/qb/xy 接入 HP（知识回流 + 检索消费），CCC 出卡/验收流程与 KB 检索、教训回流联动，底座价值兑现。

## 背景

实测发现：HP 底座能力完备但**业务项目消费不足**——mx/qb/xy 方案中 grep「知识库/KB」无实质调用；xianyu（xy）在 KB 内 0 docs；唯一有实质内容的是 qb（103 docs）。底座搭好了没人用 = 价值未兑现。

## 方案内容

分 5 个子节点执行：

**5.1 mx 接入**：medio-0 方案/教训/决策回流 HP（建立 mx 域、`/codex/topics/mx` 记忆），开发时检索历史方案/教训。

**5.2 qb 深化**：qb 已有 103 docs，深化消费——回测结果/教训/决策沉淀 + 开发检索。

**5.3 xy 接入**：xianyu 建立知识域（现 0 docs），项目知识/决策/教训入 HP。

**5.4 流程集成**：CCC 出卡/验收时 KB 检索 + 教训回流自动触发（Doc-Gate 四问联动、方案检索历史），把「查知识、记教训」变成流程动作而非自觉。

**5.5 质量回检**：消费方反馈 → 检索质量闭环（消费数据驱动 M4 质量优化迭代）。

## 验收标准

- [ ] qb 深化消费（回测教训/决策入 HP）
