## 一、目标态（一句话）

**Codex 驱动自动化流水线：出卡模板化 → Engine 按卡头派发（2017 执行体在 2017 dev worktree 开发）→ 机器验收门禁 → Codex 只留验收+放行；Nginx 统一入口；知识库 MCP 供大脑与执行体查询。**

## 二、六个模块

### 1. 出卡自动化
- 卡模板固化（T-A1 命名规则提前启用：`<前缀><三位序号>-<slug>`）。
- 大脑对话出卡（T49 能力）——Codex 在对话里让大脑产卡草案，Codex 审核后落卡。

### 2. 派发自动化（开发迁移 2017，核心决策）
- **推荐方案：2017 建独立开发 worktree**（`/Users/fan/program/ccc-dev-ws`，分支开发）：
  - 执行体（2017 的 OpenCode/Claude Code，走 6100 同一推理链路）在其中开发 → push 分支 → Codex 验收 → 合入 main → M1/2017 运行副本 pull；
  - 2017 运行副本仍只 pull 不手改（dev worktree 与运行副本隔离）；
  - Engine 按卡头绑定派发自研卡（T39 已具备），执行体在 dev worktree 自动开工。
- 备选（不推荐）：保持 M1 开发副本 + 模型出口统一 6100——简单但"开发工具在 2017"名不副实。
- 需要老板确认：2017 资源（16G 内存/磁盘）与开发交互方式（SSH CLI 无头 or 远程桌面）。

### 3. 验收自动化
- validate.py 卡头门禁（已有）+ 接入 CI/pre-commit；
- headless 复验脚本固化（免登录/流式/切界面/思考渲染场景一键跑）；
- 验收清单模板（卡回写区自动核对项）。

### 4. 部署自动化（一键放行）
- 放行脚本：`bash deploy/release.sh <commit>` = 2017 pull + 三服务 kickstart + health/board/对话自动验证 + 回写卡头「已关闭」。
- Codex 只执行放行脚本 + 看结果。

### 5. Nginx 统一入口
- 2017 上 Nginx 反代 7788（web-server）：统一 `http://<内网主机>/` 入口；
- 路径收敛（/conversation /board/* /projects /config 等）、静态缓存、访问日志；
- TLS 可选（内网自签，后续做）；域名可选（`ccc.lan` 内网解析）。

### 6. 知识库 MCP 优化（老板点名）
- 现状：`server/kb/mcp_server.py`（stdio）存在但**无调用方**；大脑直接 `search.py`。
- 优化：① kb MCP 接入调用方（大脑/执行体经 MCP 查知识库，统一查询入口）；② 索引增量更新（mtime，T-A2 同款）；③ BM25 质量调参 + 域过滤；④ 后续可选向量化。

## 四、需老板确认的决策点（我的推荐已写明）

1. **开发迁移 2017 方式**：推荐 2017 dev worktree（符合"开发工具在 2017"）；确认 2017 资源与交互方式。
2. **Nginx 形态**：推荐内网 80 反代 + 可选 TLS/域名；先不加公网。
3. **自动化边界**：Codex 保留「验收 + 放行 + 冲突仲裁」；出卡/派发/测试门禁全自动。
4. **知识库 MCP 优化优先级**：P1 并行（不依赖 T46/T47）。

> 本草案未动手；老板确认/调整后出正式实施卡（单张推进）。

## 五、测试任务先行（老板补充 1，硬性流程）

**任何正式自动化任务前，必须先跑一条测试流程任务（T9x-test），全流程跑通后删除，再开正式任务。**

流程：出测试卡（看板可见）→ Engine 派发 → 2017 dev worktree 开发（最小改动，如 echo/占位）→ push → Codex 验收 → 放行部署 → **删除测试卡 + 看板重导出无残留** → 正式任务。

测试卡的验收标准：与正式卡同款门禁（validate/测试/headless），但内容为占位改动；跑通的标准=全链路状态流转正确 + 看板可见 + 无残留。

## 六、看板可见性（老板补充 2，要求）

**自动派发的任务必须能在看板直接看到。** 机制确认：

- 看板 = 派生视图，`/board/*` API **每次请求实时读卡**（docs/dispatch 卡头状态）——Engine 派发（待分派→执行中）或回写（→已回写/打回）后，**刷新看板立即可见**，无需重启服务；
- 对话右栏卡流 12s 自动轮询，Engine 派发后 ≤12s 可见；
- `board.js` 静态导出由 board-scheduler 定时刷新（作零 API 回退）。
- **秒级实时推送**（无需手动刷新/等轮询）：T49 的 task_status 事件回流对话 + 看板 SSE 订阅——列入 T49/T50 实现，测试任务先行阶段用「刷新/12s 轮询」即可验收。
