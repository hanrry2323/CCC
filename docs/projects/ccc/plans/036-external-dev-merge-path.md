## 目标

为「不走标准出卡流程的外部开发（DSH 独立开发 / 直调开发）」建立固定合入路径，消除合入时门禁反复拦截、人工逐项补课的低效循环。

## 背景（证据）

2026-08-17 hp044 合入实录（DSH 独立开发首例）：

1. **门禁第一次拦截**：分支信封无机审区（终版实现未过机审）→ 补录异席机审区（`> 结论：机审通过`）后通过。
2. **门禁第二次拦截**：Doc-Gate Q2 教训路径 `lessons.md` → 修正为 `docs/lessons.md`（业务仓实际路径）。
3. **业务仓分叉**：rebase 分支到业务 main（lessons.md 冲突，两侧合并保留），ff-merge 收口后删分支。
4. **踩坑**：机审区 `> 状态：机审通过` 被 parse_metadata 误当卡头状态 → 改为 `> 结论：`。
5. 28 张卡集中回收期间，还顺手修复了**多处 Doc-Gate 钩子声明不实**（Q2/Q3 谎报）与 business docs 冲突。

## 方案内容

### 一、外部开发合入标准路径（补课三步法）

外部开发（DSH/直调）合入 CCC，固定三步，缺一不可：

1. **补异席机审区**：终版实现必须过异席机审（LLM 门禁），结论行用 `> 结论：机审通过`（格式见 ccc-plan-035 契约）。
2. **补维护区四问**：`## 维护区` 四问必填（方案同步/教训沉淀/README/线路图），路径与业务仓实际一致。
3. **业务仓收口**：rebase 到业务 main 解决冲突 → ff-merge 收口 → 删分支；CCC 仓分支文档 merge 进 main。

### 二、代码/门禁改动

1. 合入门禁错误信息可读化：被拦时提示「缺什么、补哪里、参考哪份文档」（当前只报失败不指引）。
2. Doc-Gate 钩子声明不实检测：Q2/Q3 填「有」但路径文件不存在 → 门禁直接报路径校验错误（防谎报）。

### 三、文档改动

1. 补课三步法写入 `docs/projects/onboarding.md`（外部开发合入专节）。
2. ccc-plan-029 的 DSH 接入规范引用本方案（DSH 作为一等执行体时同样走此路径）。
