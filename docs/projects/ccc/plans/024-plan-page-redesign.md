## 目标

计划页彻底重构：以 CCC 真实流程（方案五态 → 人触发转卡 → 卡六列生命周期 → 人合入收口）为骨架，方案卡直接显示「卡流程进度」，一眼看出方案在流程哪个环节、哪里卡住；彻底解决卡片文字遮挡与布局漂移。

## 背景

老板 2026-08-12 评审：卡片文字显示不全被遮挡、区域漂移；要求深度读取 CCC 流程后按流程重构。流程依据（权威）：DOC-PROTOCOL §2.8 方案五态（草案→已确认→部分执行→已完成→作废）、card-hub-manual §2.5/§3（转卡由人触发，new-card.sh 生成卡进看板）、看板六列（待分派/执行中/机审/已回写/打回/已关闭）、accept-board-sop（人「合入批准」收口）。

## 流程映射（页面如何反映流程）

```text
方案池（本页）              看板卡生命周期               收口
草案 ── 已确认 ── 部分执行   转卡→待分派→执行中→机审→已回写→已关闭   合入批准
                   （转卡）      └── 打回（人介入重分派）──┘
```

- 方案「部分执行」= 已转卡；「已完成」= 关联卡全部关闭（DOC-PROTOCOL §2.8）
- 计划页职责：方案池 + 关联卡流程进度 + 人触发动作（转卡/改状态），不代执行、不全自动

## 页面设计

### 一、五态流水线（保留流程语言）

- 五列 = 五态（定死），列头带状态含义副标题（草案=待讨论 / 已确认=待排期 / 部分执行=已转卡 / 已完成=卡全关 / 作废=不再执行）
- 默认显示三活跃列（草案/已确认/部分执行），终态列（已完成/作废）按钮切换——布局稳定，列数固定
- 列可折叠、计数徽标；项目筛选 + 搜索 + 密度切换（舒适/紧凑）

### 二、方案卡 = 方案信息 + 卡流程进度

卡片结构（等高固定 156px，信息完整不遮挡）：
```text
[项目徽标] [#编号]                       [打开 ▸]
标题（2 行截断）
作者 · 工具 · 更新日期
[流程条：转卡▮▮ 执行▮ 机审▮ 待合入▮ 关闭▮▮▮ 打回▮]   ← 关联卡按看板六状态分布
[计划][缺口][警示]                    验收 2/5
```

- 流程条：迷你堆叠进度条，每段=关联卡在对应看板列的计数（hover 显示明细）
- 标签：计划（已确认/部分执行可转卡）、缺口（验收未满）、警示（关联卡打回/漂移/缺失/未关闭）
- 无验收项/无关联卡有明确占位（不空白、不压缩）

### 三、动作（人触发，与流程对齐）

- 转卡：仅已确认/部分执行可点；前置显示「将生成 N 张卡」+ 确认；转卡后方案自动进「部分执行」并写关联卡
- 改状态：拖拽跨列 + 列内下拉双通道；非法流转前端预判 + 后台白名单兜底（DOC-PROTOCOL §2.8 流转）
- 详情面板：方案正文 + 验收清单（可勾选状态展示）+ 关联卡列表（每卡：状态徽标 + 所属列 + 跳看板）

### 四、稳定性（修遮挡/漂移）

- 等高卡：grid-auto-rows 固定 + 卡片 overflow hidden + 内容层截断（标题 2 行 / meta 1 行 / 标签与验收一行）
- 布局零漂移：列数固定（3/5）、容器 min-height 固定、切换项目/筛选保滚动位、禁重排动画
- 卡片信息层级：头/标题/元信息/流程条/标签+验收 五行，各自 flex 约束，不互相挤压
