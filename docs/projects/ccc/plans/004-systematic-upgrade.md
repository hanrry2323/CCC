## 二、全局问题全景（两层）

### 架构层（结构性 · 4 主题）

| 主题 | 实质 | 现象证据 |
|------|------|---------|
| **A. 内外仓流转凭证化** | 内仓（CCC 控制仓）与外仓（项目业务仓）之间无结构化凭证，控制平面用「本地视图」猜数据平面事实 | P1 门禁误判（`main.py:928-956` 用 `origin/main..HEAD`）、P2 sidecar 撕裂（`store.py:143-151` runtime 覆写磁盘真值）、机审假阳性（`models.py:73` 行内 ✅ 即通过）、合入跨仓收口复杂、xy026 产物从未落地 |
| **B. worktree 生命周期** | 有生无死：清理条件「分支已合入 main」在 close-only 模式下恒假 | 47 个本地残留分支；重试复用脏本地状态（`main.py:801` 重试复用 worktree） |
| **C. 调度韧性** | 无退避/无熔断/无自愈，槽位被死循环吃光 | P4 轰炸式重试（xy018×20、mx015×21）、P5 SIGTERM 悬挂（plist unload 断裂） |
| **D. 流程规范固化** | 60 卡跑出的纪律未固化成硬约束 | P3 空提交误判（`main.py:953` nonzero 直接判失败）、空回写卡、卡头状态乱改 |

### 流程层（现象清单，随架构修消失，不单独打补丁）

空提交/干净树误判 · 机审反复拉起 · 假失败/超时占比 · ff-only 部署断裂 · 机审区格式（多轮追加、✅ 单元格）· 回写凭证仅口头要求

## 三、方向主线（一句话）

**把任务生命周期从「本地视图驱动」改为「远端凭证驱动」**：派发→执行→产物→门禁→机审→合入→清理，每一环都基于内外仓远端凭证判定，一次闭环。四个主题挂在同一条主线上。

## 五、批次划分与验收指标

原则：按主题推进，每批 = 可测目标 + 基线指标对照（60 卡基线：61.3h/314 事件/假失败率/重试次数）。

| 批次 | 主题 | 可测目标 | 验收指标 |
|------|------|---------|---------|
| 1 | A 判定真值 | 机审/门禁只认结构化结论（修 P6 + 门禁凭证化骨架）；4 问题卡按新机制重处置 | 机审假阳性=0；hp009/xy024 重新判定不通过；xy026 补凭证或打回 |
| 2 | A 闭环 | 合入自动收口（approve-merge 一键化+sidecar 同步+清理）；修 P2 | 合入后 runtime 与 main 一致；无僵尸机审 |
| 3 | B 生命周期 | worktree 回收机制（远端分支已删+卡已关闭即清）；重试重置 | 残留分支归零；重试不复用脏状态（P1 灭） |
| 4 | C 韧性 | 指数退避+全局熔断（5 次强制打回）+kickstart 重启+看门狗 | 单卡重试 ≤5；无槽位饥饿；SIGTERM 后自愈 <60s |
| 5 | D 规范固化 | 卡模板/回写凭证字段/状态机校验器落地；修 P3 | 空提交假失败=0；空回写卡=0 |
