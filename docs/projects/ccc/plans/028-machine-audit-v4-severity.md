## 目标

把机审 skill v4（通用化 + 三级 轻/中/重，qx-map `0538bef`）从 M1 案例接入 CCC 引擎正式流程——引擎感知审计 severity 并做分流：**轻问题立即修复不打回、中度维持重试预算、重度直接打回**；同时收尾全流程审计扫出的加固点（里程碑目标日期、草案来源标记）。能力集中管理（IDE 心智）仅备注为集群化开发方向，本次不实现。

## 背景

1. 机审 skill 已升级 v4（qx-map `0538bef`）：通用对抗式找茬 + 三级分级（轻/中/重），判定=三维度打分（影响面/改动深度/红线邻近各 1-3 分，合计 3-4 轻、5-7 中、8-9 重；任一维度高→强制重度）；重度机审由 fresh 独立 agent 零上下文承担；原则=轻问题立即修复不打回、重度完整闭环、高风险禁轻放行。
2. **v4 未接入 CCC 引擎**：引擎当前统一按「业务不通过→重试预算→打回」（`_fail_retry_or_reject`）处理，**读不到审计的 severity**，无法分流。
3. 全流程审计（2026-08-14 复盘）扫出的加固点：create_plan 误标批准（已修）、里程碑无目标日期、草案无来源标记。

## 方案内容

### Phase 1 · 机审 severity 分流接入引擎（重点）

1. **severity 标记格式定稿**（D1：审计输出标记）
   - 审计模型按 v4 skill 判定后，在输出写约定标记：`severity：轻` / `severity：中` / `severity：重`（或 `机审等级：…`）；不通过结论带 `（重度/中度/轻度：原因）` 变体兼容。
2. **引擎解析 `_audit_severity()`**
   - `server/engine/main.py` 审计结论解析区（`_audit_output_indicates_rejection` 1523 附近）新增 `_audit_severity(text) -> "轻"|"中"|"重"`，默认「中」。解析 `severity：` / `机审等级：` 标记 + `（重度/中度/轻度：` 变体。
3. **分流决策**（`_run_audit_worker` business 分支 3030 附近）
   - **轻**不通过 → **独立轻修复轮**（D3）：回待分派，不占现有重试预算；sidecar 记 `light_fix` 计数，超上限（默认 2）升级为中度处理（避免无限修）。
   - **中**不通过 → 现状 `_fail_retry_or_reject`（重试预算→打回）。
   - **重**不通过 → **直接打回**（D2）：不自动重试，附原因；清 sidecar。
4. **配置**：`server/config` 加 `AUDIT_LIGHT_FIX_MAX`（默认 2）等。
5. **测试**：`server/tests/test_engine_main.py` 加 severity 解析 + 三分支分流用例。

### Phase 2 · 流程加固点

- **A1 里程碑目标日期**：`server/board/roadmap.py` 里程碑加 `target_date` 字段（可选），CRUD/解析/序列化支持；前端 roadmapPage 里程碑表单加日期输入。
- **A2 草案来源标记**：`server/board/roadmap.py` 草案加 `source`（来源：老板意图/Loop巡查/外部反馈）+ `created` 日期，解析/写入/序列化支持。
- B1（create_plan 误标批准）**已完成**（`approved` 参数，仅 promote 节点①打标）。

### Phase 3 · 能力集中管理（方向备注，本次不实现）

- 痛点：机审/Harness 每次升级都要对 Mac2017 OpenCode、Claude Code 各自改心智，重复劳动；新 IDE 接入无统一入口。
- 方向（集群化开发）：把机审 skill / 项目红线 / 高风险面 / 验收格式 / 异席目标**集中一处**（中心仓），各 IDE 工具通过**注入/拉取**机制获取，而非各自维护副本；新 IDE 接入=注册 + 拉取，不做逐份心智升级。
- 本次不实现，仅备注；后续另立方案。

## 验收标准

- [ ] 引擎解析审计 severity（轻/中/重），默认中
- [ ] 轻不通过 → 独立轻修复轮（不占重试预算，超上限升级）
- [ ] 中不通过 → 现状重试预算
- [ ] 重不通过 → 直接打回不重试
- [ ] 里程碑 target_date 字段可读写/序列化/前端可设
- [ ] 草案 source/created 字段可读写/序列化
- [ ] pytest 全绿 + validate-plans 全绿
