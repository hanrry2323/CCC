## 目标

运维页「工程化待办」按 CCC 流程闸门组织显示：人审闸门（待合入/打回）→ 机审中 → 代码健康发现，每类有明确动作；数据全部来自现有后端能力，不新增存储。

## 背景

老板 2026-08-12 评审：运维布局可接受，但工程化待办要从 CCC 流程找功能、后端要深探，做显示方案。后端能力已探明：

| 后端能力 | 返回 | 对应流程闸门 |
|----------|------|--------------|
| /board/ready_for_merge | 已回写+机审通过卡 | 人合入批准（diff 审查） |
| /cards?state=打回 | 打回卡 | 人介入重分派 |
| /cards?state=机审 | 机审中卡 | 机审闸门（进行中） |
| /loop/findings | 巡查发现（缺段落/漂移/关联断裂/维护区缺失） | 代码健康 |
| /board/roadmap | 业务线路 + 漂移/缺失 | 项目健康 |
| /plans/list 关联卡 | 方案↔卡闭环 | 缺口追踪 |

## 页面设计（工程化待办主区）

### 一、三类闸门队列（按优先级）

```text
① 人审闸门（红/橙优先）
   - 待合入：ready_for_merge 卡列表 → 动作「去合入」（跳看板合入批准）
   - 打回：打回卡列表 → 动作「去重分派」（跳看板）
② 机审中（进行中提示）
   - 机审列卡数 + 最老等待时长（如有）
③ 代码健康发现（按项目分组）
   - loop findings：缺段落/状态漂移/关联断裂/维护区缺失
   - 每条动作：转卡（复制命令）/ 已处理（loop/adopt 留档）
```

- 排序：人审闸门 > 机审中 > 代码健康；打回/待合入置顶（人工动作优先）
- 计数总览：头部 badge = 三类合计；每类自带计数

### 二、项目健康卡（已有，增强）

- 保留 023 项目卡（卡数/完成率/风险），补「缺口」口径：该项目待合入+打回+健康发现计数 → 一眼看哪个项目最需要维护

### 三、螺旋循环（已有，增强）

- 五段保持；「发现」数改为本周新增（区分存量/增量），避免永久显示旧发现

## 数据与动作

- 全部只读现有端点；动作：
  - 待合入/打回 → 跳看板（#/board）由人执行（合入批准/重分派）
  - 健康发现 → 复制转卡命令 / POST /loop/adopt 留档
- 无新存储、无自动出卡（守住人审闸门）

## 验收标准

- [ ] 三类闸门显示正确、计数一致（与看板/接口实测对齐）
- [ ] 待合入/打回可一键跳看板；健康发现可转卡/留档
- [ ] 全仓测试 + ruff 通过；异席机审后部署
