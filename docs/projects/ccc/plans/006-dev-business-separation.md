## 一、背景

CCC 当前定位为"自动化开发平台"——出卡、派发、验收、合入。但随着业务项目增多，出现了一个边界问题：**闲鱼需要自动生成视频、QuantHive 需要盯盘交易、qb 需要定时回测——这些"业务运行"要不要放进 CCC？**

2026-08-09 外脑与老板讨论后，结合社区实践（GitOps 模式、Temporal/Airflow 工作流引擎、Backstage 内部开发者平台），结论：**必须分开。**

## 二、核心决策（D1-D4）

### D1：CCC 只做开发，不做业务运行

CCC 的职责边界：代码开发 → 测试 → 验收 → 合入 main → 打 tag 发布。

CCC 不做的事：定时调度、业务脚本执行、产物管理、运行监控。这些归业务线。

### D2：业务线 = 独立运行层，每个业务线自治

每个业务线（xy / qh / qb / 未来的业务项目）拥有自己的：

- 调度器（cron / launchd / 手动触发）
- 执行脚本（读 registry 获取项目路径和版本）
- 产物落点（视频文件、交易记录、报告）
- 监控告警（成功/失败通知老板）

业务线之间不统一逻辑，只共享基础设施。

### D3：CCC 与业务线的唯一接口 = git tag + registry

```
CCC 侧：合入 main → 打 tag（v1.2.0）→ 更新 registry 版本信息
业务线侧：读取 registry → 决定是否升级 → 拉取新 tag → 重启
```

CCC 不需要知道业务线怎么跑，业务线不需要知道 CCC 怎么开发。中间只通过 git tag 和 registry 耦合。

### D4：共用 registry，不共用调度

所有项目（开发项目 + 业务项目）统一在 `docs/projects/registry.yaml` 注册。CCC 看板展示全量项目，但业务线的调度器独立部署，不经过 CCC Engine。

```
               │                               │
    ┌──────────▼──────────┐      ┌─────────────▼──────────────┐

    └──────────────────────┘      └────────────────────────────┘
```

## 四、社区依据

| 模式 | 代表项目 | 核心启示 |
|------|----------|----------|
| GitOps | ArgoCD / Flux | CI 和 CD 是独立控制循环，ArgoCD 明确不做 CI |
| 工作流引擎 | Temporal / Airflow / Prefect | 业务编排只做调度+重试+状态，不做 CI/CD |
| 内部开发者平台 | Backstage（Spotify） | 共享 Catalog + 认证，但各模块独立 |
| 反模式 | Jenkins 大泥球 | CI + cron + 数据管道混在一起 → 没人敢动 |

## 五、反模式警示（Jenkins 教训）

Jenkins 被社区批评最多的一点：一个工具同时承担代码构建、定时任务、数据管道、部署脚本。结果是一套 Groovy 配置没人敢改，改一个定时任务可能炸掉 CI 流水线。

**CCC 如果也把视频渲染、交易盯盘、自动发布塞进去，会变成同一类怪物。**

## 六、待深入探讨（框架未定稿标注）

本方案只确定了"分开"这一架构基线，以下问题尚未定案：

1. **业务线的调度器怎么部署？** 每个业务线独立 launchd？还是统一轻量调度器？
2. **业务线的运行状态怎么暴露？** 需要一个统一的"业务看板"还是在各项目里自建？
3. **业务线失败怎么通知？** 邮件？CCC 看板红色标记？还是独立通知通道？
4. **业务线能不能出卡？** 比如"闲鱼视频画质有问题，需要修"——这是出开发卡还是业务卡？
5. **registry 需要扩展哪些字段？** 业务线需要 `runtime`、`schedule`、`artifact_path` 等新字段
6. **QuantHive 独立轨道的特殊性**：qh 不进 CCC 自动开发，但 qh 的业务运行（盯盘）要不要进业务运行层？

## 八、红线

1. **CCC Engine 不执行业务脚本**：Engine 只派发开发卡，不跑业务调度
2. **业务线不写代码**：业务线只运行已发布 tag 的代码，不修改代码
3. **registry 是唯一耦合点**：开发线和业务线不直接互相调用，只通过 registry 查信息
4. **Jenkins 教训铭记**：任何想把业务逻辑塞进 CCC 的冲动，先读一遍第五章
