## 功能清单

### P0 · 第一屏（核心）

1. **系统总览条**：severity 大状态徽标 + 一句话 human_line + 节点在线/服务运行/告警数 + relay 健康灯。数据：/ops/summary + /ops/relay-stats
2. **集群节点健康卡**：每节点一张卡（名称/IP/角色/在线/端口数），分组显示（核心节点 / HP 知识库）。数据：/ops/summary.machines + /ops/hp-health
3. **服务网址卡（端口探索）**：三态分组——活跃服务（绿，可点开）/ 监听未识别（橙，待人工确认）/ 登记未运行（灰，历史业务端口）；新增/消失端口提示。数据：/ops/ports（新）
4. **中转站状态卡**：健康 + 今日请求（总/Pro/flash/code）+ 近 10s 增量，15s 轮询。数据：/ops/relay-stats
5. **引擎与后台任务卡**：执行中/机审中进程（8s 轮询）+ 并发槽位。数据：/tasks/running + /ops/concurrency

### P1 · 第二屏（工程入口 + 设置）

6. **工程入口**（保留改造）：KPI 计数（五态）、待合入（ready_for_merge，跳看板）、需注意（打回/执行中）。数据：/board/states + /board/ready_for_merge
7. **设置（只读）**：平台关键配置分组展示（服务端口/模型档位/版本/并发槽位/集群目标）。数据：/config + /ops/concurrency + 环境派生

### P2 · 后置（占位）

8. **中转站管理动作**：重启/状态切换——需中转站管理接口或部署 SOP，先占位
9. **设置编辑**：改 config.env + 重启确认——需后端写盘能力，另立方案

## 端口探索设计（/ops/ports）

目标：自动发现集群实际使用端口，区分「在用 / 用了没用了 / 历史用过」，不靠手写全量清单。

1. **自动发现**：`lsof -iTCP -sTCP:LISTEN` 全量扫描本机监听端口（COMMAND/PID/PORT），零配置
2. **三态分类**：
   - active_known：监听 + 有映射（CLUSTER_PORT_NAMES / CLUSTER_BUSINESS_PORTS）→ 绿
   - active_unknown：监听但无映射（残留/未登记进程）→ 橙，提示人工确认
   - registered_stale：映射了但当前未监听（登记未运行）→ 灰
3. **业务映射**：config 新增 `CLUSTER_BUSINESS_PORTS=quanthive:3000,...`（业务名→端口），量化当前用 3000 即在运行；历史用过端口靠快照 diff
4. **快照历史**：每日端口快照落 `data/ports/YYYY-MM-DD.json`，与昨日 diff 出「新增 / 消失」端口（历史使用追踪）
5. 端口 URL：`http://<host>:<port>`，点击新窗口打开

### 状态判定矩阵

| 监听？ | 有映射？ | 判定 | 展示 |
|--------|----------|------|------|
| 是 | 是 | active_known | 绿 · 名称/URL/进程 |
| 是 | 否 | active_unknown | 橙 · 待识别（进程名） |
| 否 | 是 | registered_stale | 灰 · 未运行（业务名） |
| 否 | 否 | 不在清单 | 快照消失列表（历史） |
