## 目标

把 DSH 深度调研（25 实验 + 卡2/卡3）的收获固化收尾：**DSH 部署为独立审计席（稳妥）**，开发体替换**谨慎待 DSH 成熟**；并立项 **「任务编排/多任务执行借用 CodeRun」**为 CCC 下一步突破重点方向——CC 规范化执行流程已打通，缺的是多步骤/长任务编排能力。

**2026-08-16 老板定调（精化）**：CodeRun 是**模式**不是 DSH 专属——**先在 OpenCode（开发席）+ Claude Code（验收席）里落地 CodeRun 模式**，不等 DSH 成熟；DSH 现阶段只做独立审计席，等软件成熟后再议扩展席位。

## 背景

- DSH（DeepSeek Harness）CodeRun 范式（模型写代码、代码内调工具）已完成深度调研：源码 11 章报告 + 25 实验 + 卡2/卡3 落地（2026-08-16，Claude Code）。
- 关键实证：DSH 只读取证/审计能力强（卡3 首单 3 实锤）；CodeRun 对多工具编排任务提效明确（一轮=多子调度并发）；无沙箱（内部可信环境直接使用，老板定）；description 漏参 57%（模型纪律短板）。
- CCC 现状：**任务编排、规范化执行流程已打通**（看板 → 出卡 → Engine 派发 → 合入门禁），但**多步骤、长任务、任务编排能力尚未正式投入开发**——这是老板认定的下一步突破重点。
- CodeRun 的「程序化编排 + curated result」正是补这块能力的范式参考。

## 方案内容

### 1. 部署定位（老板定，落地）
- **DSH = 独立审计/取证席**（卡3 已验证）。部署于 Mac2017，走 headless 只读，不参与 Engine 自动派发。等 DSH 软件成熟后再议扩展席位。
- **CodeRun 模式先在 OpenCode + Claude Code 落地**（不依赖 DSH）——这是核心动作，见 §3。
- 隔离沙箱不投入（老板定：集群内可信环境直接使用）。

### 2. 调研收获固化（收尾）
- 25 实验 + 卡2/卡3 已落档：qx-map `__archive__/research/`（报告 + 汇总）+ CCC 分支 `research/dsh-eval`（experiments/）。
- 收获要点沉淀为可复用的三条（见 §4 借鉴）。

### 3. 任务编排借用 CodeRun（重点研究立项 · 在 OpenCode/CC 落地）
- **方向**：研究 CodeRun 模式解决 CCC 的「任务颗粒度」问题——从里程碑拆出的小卡本身仍是多步骤复杂任务；用**程序化编排**（一段确定性程序内并发/串行调度多个子步骤）把多步骤卡直接投递到开发环节执行。
- **落地载体**：**OpenCode（开发席）+ Claude Code（验收席）内部用 CodeRun 模式**（cc-run-inline 式内存脚本/内联程序），不是 DSH 专属。
  - 开发席：多步骤卡写成确定性程序编排（读上下文 → 并行取证 → 按步骤改 → 回写），把「N 次模型调用串联」压成「1 次写程序 + 确定性执行」——减少对模型逐跳发挥的依赖，提准确率与效率。
  - 验收席：重跑开发程序的只读部分验证（程序 + 执行日志 = dev→review 共享交接物），从「看 diff 猜」变「跑同样的操作验证」。
- **假设**（待探针验证）：① 多步骤编排提效（少模型往返）；② 上下文更省（curated result 思路）；③ 准确率提升（错误只在写程序时发生一次，且可检可回放）。
- **范围**：本方案先做**探针验证**（选真实多步骤卡，CodeRun 编排 vs 现状对比），数据达标后再写成执行约定。

### 4. CodeRun 借鉴点落卡（机制层，模型无关）
1. **curated result**：执行体回写只带结论、详情进证据链——对齐 CCC 审计契约。
2. **程序化并发编排**（Promise.all 并行）——临时 Worker 语义。
3. **fail-closed 默认**：无审批不升级、无通道即拒。

## 功能卡

> 方案 = 一个子项目（任务编排能力），节点② 老板确认后按子项目转卡。三卡按价值排序。

### 卡1 · DSH 审计席部署运行

目标：把 DSH 只读取证席从「实验验证」变「日常可用」——独立跑合规/巡检扫描，与开发/机审三席分离。

实现：① 确认 executors.json DSH 槽参数（已定稿）；② 定义 DSH 审计触发入口（headless runner，只读）；③ 接板一次真实巡检（可复用卡3 审计模板）。

验收：DSH 独立审计席可被老板按模板触发一单真实扫描，结果落档。

### 卡2 · 任务编排借用 CodeRun（探针 · 在 OpenCode/CC 内验证）

目标：概念验证「CodeRun 模式解决多步骤小卡的颗粒度问题」——在现有 OpenCode/Claude Code 流程内，选一张真实多步骤卡，用程序化编排 vs 现状逐轮调用，对比提效/准确率/上下文。

实现：① 选一张真实多步骤卡（步数多、OpenCode 现会跑几十上百次调用的类型）；② 开发席用 CodeRun 式程序编排（cc-run-inline/内存脚本：并行取证 + 串行变更 + 回写）；③ 验收席重跑只读步骤验证；④ 对比逐轮调用的轮次/耗时/上下文/准确率。

验收：探针产出「程序化编排 vs 现状」对比数据 + dev→review 交接物（程序+日志）可行性结论，落档。数据达标 → 升级为执行约定。

### 卡3 · CodeRun 借鉴点落 CCC 约定

目标：把 3 条机制借鉴写进 CCC 执行体约定。

实现：① curated result → 回写契约「只带结论、详情进证据链」；② 并发编排 → 执行体边界文档；③ fail-closed → 执行体默认。

验收：3 条写入对应文档（executors / 回写 SOP / 边界），validate-plans 通过。
