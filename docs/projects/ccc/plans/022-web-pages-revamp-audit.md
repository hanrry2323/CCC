## 方案内容

### 一、流程与后台逻辑问题（按优先级）

**P0-1 方案转卡链路缺推送（流程断点）**：`/plans/convert` 调 `new-card.sh` 只生成卡文件，不 commit 不 push；规范出卡路径 `plan-to-cards.sh` 才做 add/commit/push。转卡后卡不推远端，Engine 收不到，除非人工补推。
修法：convert 统一走 plan-to-cards 语义（卡文件生成后自动 commit+push 到卡分支），或明确约定人工统一推送并在转卡结果里提示。

**P0-2 转卡无幂等/部分失败无回滚**：多张卡转卡中途失败，已生成卡不回收、方案状态不推进；重试会重复出卡；无并发锁。
修法：转卡前预检全部行→生成失败回滚已建卡文件；成功后一次性推进状态并写关联卡；入口加并发锁与重复提交防护。

**P1-3 双解析器漂移**：roadmap 巡检存在两套解析（observer.scan_findings 宽松正则 vs roadmap_parser 严格 `[a-z]{2,4}\d{3}`），卡号格式变化时巡检结果与页面展示可能不一致。
修法：roadmap 业务线路解析收敛为单一真值模块，observer 与 web 共用。

**P1-4 验收进度统计失真**：`_extract_acceptance` 把验收标准段所有非空行计入 total（含说明文字/子标题），进度条可能虚低。
修法：只统计 checkbox 行（`- [ ]` / `- [x]`）。

**P1-5 运维采集串行阻塞**：`/ops/summary` 每次轮询对每节点 TCP 探活（单节点超时 3s），多节点不可达时 ops 15s / console 8s 轮询会挂起。
修法：节点探测并行化 + 采集结果短缓存（如 10s TTL）。

**P2-6 前端标题归纳依赖后端文案模板**：opsPage `summarizeFinding` 用正则替换后端标题，后端改文案格式前端就要跟着改。
修法：后端直接输出用户可读 human 字段，前端只展示。

**P2-7 待办最多显示 12 条**：超出部分被截断（有计数但看不到）。
修法：分页或「展开全部」折叠区。

**P2-8 运维「条目级时间轴」名不副实**：条目 ts 仍是报告文件 mtime，同批条目时间相同。
修法：报告内嵌逐条扫描时间，或前端标签改「批次扫描于 X 前」避免误导。

**P2-9 ccc 方案校验器与读写器口径不一致**：`plans.py` 的 `_get_valid_prefixes` 允许 ccc（正则匹配 registry），`validate-plans.sh` 走 `card_prefixes()` 排除 forbidden 前缀——web 端可创建 ccc 方案但校验器判非法（现有 ccc/plans/001-021 全部同样 FAIL）。修法：统一口径——ccc 方案允许存在与查看，但禁止转卡（与红线一致）。

### 三、UI/UX 设计逻辑评估与卡片化优化

设计逻辑总评：三页已形成「一页看懂 + 问题可定位 + 动作可执行」模式，方向正确；下一步把信息型卡片升级为行动型卡片，并统一三页的交互语言（状态色/徽标/空态/加载态）。

**计划页（五态流水线）**
- 已符合：五态列=业务状态机可视化；筛选/搜索/详情/新建/转卡齐全；卡片信息密度合适。
- 优化：①卡片拖拽跨列改状态（非法流转置灰+提示，后台白名单不变）；②卡片加关联卡实时状态小徽标（如 3 卡 2 关 1 漂移）；③详情页转卡按钮前置确认并展示将生成卡数；④空态/加载态统一。

**线路图页（两级钻取）**
- 已符合：一级项目卡片总览 → 二级 SVG 时间线 + 卡分组 + 风险，符合「先总览后下钻」。
- 优化：①一级/二级进度口径统一（一级按 progress 字符串匹配、二级按 normalize_state，可能不一致）；②无日期里程碑不丢弃，放「未排期」区；③里程碑节点可点击展开卡列表；④漂移/缺失卡提供「跳转看板」动作；⑤风险提示卡片化 + 三色分级（现为一行文字）。

**运维页（三层架构）**
- 已符合：结论→待办→细节，完全符合「老板先看结论、运维再看细节」。
- 优化：①健康仪表盘从一栏拆成三张状态卡（集群/服务/管道），每卡色块+一句结论；②待办卡操作扩展：现有「转卡」复制命令，增加「已处理/忽略」直接写 `/loop/adopt` 闭环留痕；③技术详情按节点分卡、端口明细可展开；④显示「上次扫描于 X 前」让采集状态可见。
