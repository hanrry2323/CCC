# 方案 · 看板与信息墙职责分离——人工任务全量上板 + 来源标记体系

> 项目：ccc · 编号：ccc-plan-048 · 状态：部分执行 · 作者：DSH（ox-alpha · 总调度） · 工具：DSH
> 创建：2026-08-24 · 更新：2026-08-24（P1 已投递）
> 关联卡：ccc079
> 关联方案：046（一期皮层）、047（二期实时通道收敛，进行中）
> 批准：老板两条基本要求 · 2026-08-24

## 目标

把两个显示面的职能定死并落地：

1. **看板**：显示一切老板手动发起的任务——CCC 自开卡（ccc 前缀平台卡）与各项目卡（xy/mx/qb/hp…）全部上板，带实时运行态；
2. **信息墙**：回归 DSH 实时会话流本职；**后台自动发起的任务一律不在信息墙显示**。

## 背景（今日实证）

- ccc 平台前缀卡因 registry category=platform 被 loader 设计性排除，看板永远不可见（ccc068-075 全部隐身）；
- /cards 叠加第二层异常：仅返回 cd/cla/clw/hp 四项目 50 张，xy/mx/qb/tst 也消失（进程内直调 loader 有 207 张）；
- 老板被迫逛三个页面找任务进度，且墙卡静默被误读为「任务停了」（字节级增长实证未停）。

## 基本要求 → 技术判据

| 要求 | 判据 |
|---|---|
| R1 人工任务全量上板 | loader 取消 platform 豁免；/cards 修复四项目缺失；看板前端兼容渲染平台卡 |
| R2 后台任务不上墙 | 卡片引入来源字段 origin∈{manual,auto}；信息墙会话卡片按关联任务的 origin 过滤 |

## 分期实施

### P1 可见性统一（本方案主刀）
1. loader：移除 platform 前缀扫描豁免（`_platform_prefixes` 调用点改为恒空集，保留函数与注释记录设计变更）；
2. 排查并修复 /cards 四项目缺失（嫌疑：web-server 进程 `_DISPATCH_DIR`/index 解析的环境耦合，或 _compose_board_items 合成丢项；以进程内逐项目计数日志定位）；
3. 看板前端：项目筛选器增加「ccc/平台」组；卡片渲染兼容平台卡无业务仓字段的形态；
4. 验收：打开看板可见 ccc070-075（历史已关闭）与 076/077/078（在途）全量卡片及运行态徽章；/cards 项目集合 ⊇ {cd,cla,clw,hp,xy,mx,qb,tst,ccc}。

### P2 来源标记体系
1. CardHeader/BoardItem 增加 `origin` 字段（manual/auto），存量卡 loader 缺省回填 manual；
2. 出卡工具（new-card.sh / dsh-card-maker）写 `> 来源：手动`；为未来后台自动化预留 `> 来源：后台` 写入口径；
3. 看板对 auto 卡显示「自动」徽章（是否上板=后续决策点，本期仅数据到位）；
4. 信息墙：会话卡片如能关联到 origin=auto 的任务则不渲染任务语义（保留会话流本体）——关联依赖 P3 心跳层，本期先落数据基础。

### P3 身份关联与全链追溯（总调度令 · 深度绑定的核心要求）

> 老板原话定调（2026-08-24）：结合 DSH 每任务都有轨迹的方式，**对每个任务进行回溯和追溯**是 CCC 与 DSH 深度绑定的非常重要的点——要高效利用该机制，而不是让 Agent 每次到处追查。

升级为一级交付物：

1. 执行体运行期写结构化心跳 `~/.ccc/logs/exec/<id>.heartbeat.json`：必须含 `card_id`、`session_id`、`workspace_key`、`phase`、`last_tool`、`bytes_progress`、`ts`（≥5s 一跳）；
2. 心跳按卡聚合为索引（`data/trace/card-sessions.json`）：卡号→会话 id 双向可查，看板卡片「轨迹」按钮直达信息墙对应会话卡；Agent 查进度=读索引一次，禁止全盘扫目录；
3. 存量补录：以 sessions 目录名内嵌的 worktree 路径反解卡号（当前唯一事实关联）批量回填索引；
4. 验收：任取一卡，一条命令返回其全部会话轨迹路径与当前阶段。

## 验收标准

- [ ] 打开看板：ccc070-075 与 076/077/078 全量可见，运行态徽章正确
- [ ] /cards 项目集合覆盖全部 taskable+platform 项目
- [ ] 信息墙无任务清单语义混入；后台任务出现时有数据字段可过滤
- [ ] 全量 pytest 绿；既有四项目看板显示零回归

## 边界

- 不动 047 的实时通道收敛工作（分支开发制并行不冲突：本方案动 loader/web-server 数据层，047 动前端页面交互层，合并时以 main 为准协调）；
- 平台卡上板后是否参与「五列工作列」流转语义，随 P1 上线观察后再定。

## 显示面独立红线（2026-08-24 总调度令 · 最高标准）

1. **信息墙 = 会话沟通面**：老板与各 Agent 的对话在此同屏实时呈现（多会话同屏 / 及时纠偏 / 移动办公）；原子=session；不承载任务清单语义；后台自动发起的任务不得以任务形态上墙。
2. **看板 = 任务状态机 + 全链追溯面**：人工发起的任务全量上板（含平台卡）；每张卡可查询所处流程节点，并经 P3 追溯索引直达其 DSH 会话轨迹。
3. 两面各自独立；任何前后台逻辑设计与冲突，一律以本底层逻辑裁决。
