## 目标

定义「螺旋上升」闭环的**人审合并环节**——老板定期与 Claude 沟通，把巡检结果、草案池、未开发方案**合并**成新的开发计划/里程碑，再拆任务卡进入下一轮开发循环。这是螺旋的「决策层」，让「发现」能变成「开发」。

## 背景

螺旋上升闭环当前状态：
- ✅ **DSH 全局跑通核实**（每 6h cron + 合入即时触发 + scheduler 兜底）→ 发现自动进巡检页 + 草案池
- ✅ **LoopObserver**（定时规则巡查）→ 治理漂移自动修复 + consistency/tech 自动进草案池
- ✅ **草案池**（各项目 roadmap.md `## 草案池`）→ 巡检发现自动进（source=DSH / Loop巡查）
- ✅ **开发流水线**（方案→里程碑→拆卡→开发→机审→合入）
- ❌ **人审合并环节**（发现→决策→计划的转换）没有固定流程

老板要的闭环：**发现（巡检）→ 进草案池（固定地方）→ 人审（合并决策）→ 拆计划/里程碑 → 开发 → 合入 → 再巡检（螺旋上升）**。

## 方案内容

### 1. 人审合并流程（固定节奏）

**触发**：老板主动召集（每周/每里程碑/发现积压时），或 Claude 在早报/巡检积压时提醒。

**输入三源**（人审前 Claude 准备好）：
1. **巡检发现**：巡检页（#/dsh）最新 DSH 报告 + Loop 报告（按项目分组）
2. **草案池**：各项目 roadmap.md 草案池（含自动进的 DSH/Loop 草案）
3. **未开发方案**：待排期方案 + 未拆卡的功能卡

**人审步骤**（Claude 主持，老板决策）：
1. **拉取汇总**：Claude 读取巡检页 findings + 各项目草案池 + 待排期方案，整理成「合并视图」（按项目/主题分组）
2. **逐项决策**：每条草案/发现判定——
   - **采纳** → 提升为方案（`promote_draft_to_plan`）→ 定里程碑 → 拆卡
   - **合并** → 多条相关发现合并成一个方案
   - **暂缓** → 留草案池（不占开发资源）
   - **驳回** → 从草案池移除（`remove_draft`）
3. **制定计划**：合并后的方案 → 定里程碑（roadmap.md `## 里程碑`）→ 方案转功能卡（`convert_plan`）
4. **进入循环**：新卡 → 待分派 → Engine 派发 → 开发 → 机审 → 合入 → 触发 DSH 复核（螺旋上升）

### 2. 人审决策依据（发现如何处置）

| 发现来源 | 类型 | 处置建议 |
|---|---|---|
| DSH 全局跑通 | 真实应用跑通失败 | 高优先：立即出卡修（提升为方案→拆卡） |
| DSH 全局跑通 | bug / 隐患（action=改/删） | 采纳→方案→拆卡；合并同类 |
| DSH 全局跑通 | 提升点（action=留） | 暂缓留草案池，或合并进规划 |
| Loop 治理 | 状态漂移（已自动修复） | 人审确认修复结果，无需出卡 |
| Loop 治理 | 技术债/治理债（已入草案池） | 按优先级采纳/暂缓 |
| 草案池存量 | 历史想法 | 逐条采纳/暂缓/驳回 |

### 3. 与现有机制衔接

- **草案 → 方案**：`roadmap.promote_draft_to_plan`（roadmap.py:683，人审节点①，前端「确认转方案」按钮）
- **方案 → 卡**：`convert_plan`（plans.py:1024，人审节点②，前端「转为任务卡」）
- **巡检页**：`#/dsh`（DSH 报告）+ `#/ops`（Loop 报告），按项目分组
- **草案池查看**：线路图页 `#/roadmap`（roadmapPage.js），草案卡片化 + 确认转方案

### 4. 输出物

人审完成后，Claude 输出一份「人审纪要」：
- 采纳了哪些（草案→方案，含里程碑归属）
- 合并了哪些（相关发现→一个方案）
- 暂缓/驳回了哪些（留草案池/移除）
- 新增里程碑/方案列表

纪要落 `docs/notes/YYYY-MM-DD-spiral-review.md`，供追溯。
