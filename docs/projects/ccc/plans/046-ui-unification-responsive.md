## 目标

以信息墙为设计模板，统一七视图的视觉语言与组件构造（栏+卡片为主形态）；
建立 PC/平板/手机三端一致的响应式标准。全程工程化推进：调研→规范→分期开发→逐期验收→版本管理。

## 一、现状审计（2026-08-24 实测数据）

### 1.1 风格不统一的量化证据

| 维度 | 事实 |
|---|---|
| 卡片组件 | 六套命名体系零复用：`board-card` / `pcard`(plans) / `rm-card`(roadmap) / `console-card` / `ops-card` / `dsh-sum-card` |
| 设计令牌采用率 | 墙 wallPage+wall.css 用 27 个 `--ccc-*` 令牌；boardPage 6 个；plansPage/consolePage/opsPage 的 JS 内联样式 **0 个** |
| 硬编码颜色 | plansPage.js 内联 18 个唯一 hex（最严重）；boardPage 3 个；components.css 全文件硬编码 hex 115 处（Top：#c96442×20、#c47a2c×11——均为主题色的「手抄副本」，改主题即脱钩） |
| 断点体系 | 全站 34 种断点取值（768/900/960/767/720/640/1600/1200/1280/380/320…各凭手感），无刻度定义 |
| 移动端 | components/shell 的 @media 全部是旧对话组件的局部补丁（composer 侧栏/看板列宽）；hub-nav 7 链接在窄屏无任何适配方案；六页面均无手机布局 |
| CSS 体量 | components.css 4529 行 + shell.css 3829 行，其中大量已死对话样式未清 |

### 1.2 信息墙为什么能当模板

wall v0.3.4 已实证的设计语言恰好是目标形态：
- **纯令牌驱动**：27 个 `--ccc-*` 语义令牌，零硬编码色，深浅主题一键切换
- **栏+卡片主形态**：弹性横轨 `.wall` + `.cell` 卡片（clamp 流体列宽 `clamp(320px,28vw,380px)`）
- **结构化卡片**：格头 28px（标题+徽章+状态点+时长+操作钉右）/ 内容区 / 格脚 22px（元数据行）
- **完整三端**：手机竖屏单格轮播（scroll-snap）、横屏三栏、平板字号升档、粗指针触控目标 ≥44px、reduced-motion 降级、iOS 输入 16px 防缩放
- **状态视觉语义**（046 前置优化已落地）：绿脉冲=运行中 / 红闪=异常 / 橙静止=待人工 / 灰弱=完成

## 二、目标设计语言（以墙为规范的提炼）

### 2.1 页面骨架（七视图统一）

```
┌─ hub-nav（壳级，已有）──────────────────────────────┐
│ view-* 容器                                          │
│  ┌ .page-topbar（32px：页标题 + 关键统计 + 主操作钮）┐ │
│  ├ .page-body                                       │ │
│  │   栏（grid/flex 列）× 卡片（.k-card）             │ │
│  └ └──────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────┘
```

### 2.2 统一令牌扩展（variables.css 追加，全站唯一定义）

| 组 | 新增令牌 |
|---|---|
| 状态色 | `--ccc-success/-warn/-danger`（已有）+ `--ccc-info` |
| 间距刻度 | `--ccc-space-1..8`（4/8/12/16/20/24/32/40px） |
| 字号阶梯 | `--ccc-font-size-xs/sm/base/lg/xl`（已有，明确用途映射 10.5/12/14.5/16/20px） |
| 圆角 | `--ccc-radius-sm/md/lg`（已有，映射 5/8/12px） |
| 高度 | `--ccc-h-topbar:32px; --ccc-h-card-head:28px; --ccc-h-card-foot:22px; --ccc-h-control:44px(触控)` |

### 2.3 共享组件层（新增 css/ui-kit.css，全部走令牌）

| 原语类 | 取代 |
|---|---|
| `.k-page`（页容器：内边距/滚动/最大宽度） | 各页 hub-page 自定义 padding |
| `.k-topbar`（32px 页头：标题/统计区/动作区三段） | ops/console/plans 各自的 bar 实现 |
| `.k-card`（卡片基底：surface 底/边框/圆角 12/阴影/悬浮态） | board-card/pcard/rm-card/console-card/ops-card/dsh-sum-card |
| `.k-card-head/.k-card-foot`（28/22px 头脚结构） | 各页私有 head/meta |
| `.k-chip`（统计芯片）/`.k-badge`（语义徽章：含 success/warn/danger/info 四态）/`.k-dot`（状态点） | badge/ops-chip/qa-chip 等散落实现 |
| `.k-btn`（按钮：primary/ghost/danger 三态，触控 44px） | hub-btn 分散变体 |
| `.k-empty`（空态）/`.k-loading`（骨架） | 各页 empty/loading 写法 |

原则：**ui-kit 只加不改**——M1 落地后各页在 M2 逐一把私有类替换为原语类，
页面特有样式留在自己作用域（如 `#view-wall .cell` 特有部分保留）。

### 2.4 三端响应式标准（业界通行做法的裁剪版）

| 项 | 规范 |
|---|---|
| 断点刻度 | 全站仅允许 4 个：**sm 640 / md 768 / lg 1024 / xl 1280**（纯 CSS 无法用变量做 media query，四值写死并入规范文档；现有 34 种断点在迁移中归并） |
| PC（≥1024） | 多列栅格/看板列完整形态 |
| 平板（768–1023） | 列数收缩（grid auto-fill + minmax 流体列宽，参照墙 clamp 手法） |
| 手机（<768） | ① 栏→纵向堆叠或横向轮播（scroll-snap，参照墙手机族）② 表格/宽组件降级为横滚容器或卡片堆叠 ③ 触控目标 ≥44px ④ iOS 表单字号 ≥16px 防聚焦缩放 ⑤ `viewport-fit=cover` + 安全区 padding ⑥ hub-nav 移动端收敛为品牌+关键视图横向滑动条（参照墙 topbar flex-wrap 方案） |
| 无障碍 | prefers-reduced-motion 全动画降级（墙已有范式推广全站） |

## 三、分期计划（工程化推进）

### M1 设计基座（纯加法，零行为变化）
variables.css 令牌扩展 + ui-kit.css 原语层 + 规范注释。验收：现有页面零变化（截图对照）；
令牌/ui-kit 均有注释契约。

### M2 六页逐页迁移（每页一个独立 commit = 一个可回滚单元）
顺序按混乱度：**plans（18 色+0 令牌，最重）→ console → ops → roadmap → board → dsh（已最近似，最轻）**。
每页动作：私有卡片类 → `.k-card` 族；内联硬编码色 → 令牌；页头 → `.k-topbar`；
空态/加载态 → 原语。行为逻辑一律不动。
每页验收：① 功能回归清单（该页交互逐项点验）② CDP 断言（DOM 结构/令牌引用计数）③ 三端截图入 `docs/qa/ui-unification/` 基线库。

### M3 三端专项
hub-nav 移动端形态定稿与实现；各页手机布局规则落地（堆叠/轮播/横滚决策表）；
触控/安全区/reduced-motion 全站扫尾。验收：真实手机 + 平板实测走查（老板抽查），
CDP 三视口（375×812 / 820×1180 / 1440×900）× 七视图截图矩阵全量入库比对。

### M4 存量清理
components.css/shell.css 中已死对话样式删除（预计可减 30%+ 体量）；断点归并收尾；
`?v=` 静态版本戳升级机制沿用。

## 四、验收标准（总体）

- [ ] 七视图任意互切视觉连贯：同一卡片在不同页呈现一致（同令牌同结构）
- [ ] 全站 JS+CSS 硬编码 hex 从 133 处降至 ≤10 处（白名单例外须注释理由）
- [ ] 断点从 34 种归并为 4 种标准值
- [ ] 三端截图矩阵（3 视口 × 7 视图 × 深/浅主题 = 42 张）入库 docs/qa/ 并与实现一致
- [ ] 每页功能回归清单通过；pytest 全量绿
- [ ] 每期独立 commit 可单独回滚；静态版本戳随发布递增

## 五、风险与边界

- components.css 是多页共享文件：M2 迁移期间新旧类并存，删旧类必须等该页迁移完成且截图对照后
- 墙作为模板但不是照抄：其他页是「数据面板」不是「会话流」，取其令牌/结构/三端策略，
  不取其横轨轮播交互（仅手机端看板列等场景选择性借鉴）
- 大改期间冻结新页面样式需求，避免双线作战
