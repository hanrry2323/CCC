对重建期遗留的两个隔离活口——dsh-web（node 804，监听 `*:3080`）与 06:05 巡检 cron（`ccc-prod-health.sh` 服务段化石）——给出唯一处置建议：**dsh-web 关停（不改造复用）；巡检 cron 保留并改造脚本服务段**。

## 方案内容（唯一建议）

### 处置一：dsh-web → **关停**（不改造复用）

1. `kill 804`（或 `killall -9` 兜底）；无守护故无需 unload。
2. 不做任何自启登记；需要 DSH web UI 时**按需手动拉起并绑 `127.0.0.1:3080`**（加 `--host 127.0.0.1` 类参数，先与 DSH 侧确认参数名）。
3. 拓扑文档（docs/deploy/topology.md）记一行「2017 dsh-web 已退役，如需 UI 手动拉起仅绑回环」。

**理由（为何不改造复用）**：全仓零依赖、零使用证据；改造绑回环+加守护的工程投入换不来任何在用链路；关停后如真有需求（人会提），再按需起即可，回退成本≈0。

### 处置二：06:05 cron → **保留 + 改造脚本**（不关停）

1. 改 `~/.dsh/ccc-prod-health.sh`「## 服务」段：删除四个化石 launchd 标签查询，改为（与 ccc-plan-052 第 1 期对齐）——
   - web:7788 `/health` 探活（已有，保留）；
   - 若 052 第 1 期落地：改查新服务集（如 `com.ccc.engine`、`com.ccc.phase2`）的 launchctl 标签；
   - 588 保留 6100 退役断言与磁盘段不动。
2. 输出文件追加「stale 段已移除」注释行，便于日志比对。
3. cron 表本身不动（06:05 节奏无变化）。

**理由（为何不关停）**：巡检快照（HTTP/磁盘/退役断言）仍在产出真实价值；化石的只是服务段——改脚本比废巡检便宜且消除每日假告警。
