## 目标

统一机审区格式契约，杜绝「审计 Agent 输出格式与解析器假设不符 → 机审通过但落盘失败 → 死循环」类问题，让机审区写入/解析/门禁三段对同一标准。

## 背景（证据）

2026-08-17 三起同源事故：

1. **机审落盘失败死循环**：`server/board/models.py:94` 解析器读取 `## 机审区` 时忽略所有 `###` 开头行，而 2017 审计 Agent 输出 `### 机审：通过` → 误判无结论 → 机审通过但落盘失败 → 冷却死循环，hp032/hp038 卡死无法合入（已热修：忽略 `###` 时排查是否含「机审/结论/结果」字样）。
2. **parse_metadata 全文扫 `>` 行**：机审区 `> 状态：机审通过` 被 `parse_metadata` 全文扫 `>` 行误当成卡头状态（`meta["状态"]` 后写覆盖）→ loader 测试失败 `state='机审通过'`（hp044 实测踩坑，已改为 `> 结论：`）。
3. **无成文规范**：审计 Agent 输出格式靠经验，无权威契约文档；DSH 审计执行体（ccc-plan-029 定位）接入时同样面临格式对齐问题。

## 方案内容

### 一、机审区格式权威标准（契约正文）

机审区内固定两类行，其余自由：

- **结论行**（解析器唯一依据）：`> 结论：机审通过` / `> 结论：机审不通过`（或 `**机审：通过**` 兼容行）。
- **元数据行**：一律 `> 结论：` 前缀，**禁止 `> 状态：` 前缀**（会被 parse_metadata 误当卡头状态覆盖真值）。
- **层级标题**：允许 `### 机审：通过` 等 `###` 行，解析器已兼容（含结论字样不忽略）。

### 二、代码改动

1. 机审区格式校验器：审计落盘前校验结论行格式，非法格式当场报错打回（防静默降级）。
2. `parse_metadata` 加固：仅解析卡头元信息区，不全文扫 `>` 行（或对 `## 机审区` 之后的内容明确豁免）。

### 三、文档改动

1. 契约正文写入 `docs/projects/onboarding.md` 机审区规范段 + 本方案登记为权威源。
2. 2017 审计 Agent / DSH 审计执行体的机审输出模板对齐契约。

## 验收标准

- [ ] 机审区结论行/元数据行格式有权威契约（onboarding 成文）。
- [ ] 非法机审区格式（如 `> 状态：`）在落盘时被校验器拦截并报错，不再静默污染卡头状态。
- [ ] `### 机审：通过` 与 `> 结论：机审通过` 两种写法均被正确解析，单测覆盖。
- [ ] hp032/hp038 死循环类问题无复发路径（解析器双保险 + 校验器前置）。
