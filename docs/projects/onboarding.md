# 从零到一：项目准入与开发规范（ONBOARDING）

> **来源**：clwarp 首次从零全流程开发复盘（2026-08-09）。
> **定位**：taskable 项目从注册到日常开发的全流程规范；与 [`DOC-PROTOCOL.md`](../DOC-PROTOCOL.md) §2/§3 配套（命名/注册口径以 DOC-PROTOCOL 为准，本页管流程与门禁）。
> **核心**：**看板是项目维护的核心**——任何 Agent 打开 CCC 看板（`http://192.168.3.116:7788/#/board`）就能找到每个项目的全部核心基准文件。

## 1. 注册（准入）

### 1.1 唯一事实源

`docs/projects/registry.yaml`。派生（`GET /projects`、PREFIXES、`is_taskable`、出卡校验）全部自动，**禁止手维第二份真值**（种子文件、kb-seed、各页硬编码表一律不碰）。

### 1.2 注册动作（SOP，缺一不可）

1. `registry.yaml` 加条目：`prefix`（2-4 位小写，不得与既有冲突）、`id/name/display`、`location`（须在归属树内，见 DOC-PROTOCOL §3.1）、`taskable`、`status`。
2. `docs/projects/<prefix>/README.md`：**七节档案**（§2.2 模板）。
3. `docs/projects/README.md` 前缀索引表**同步加行**。
4. 业务仓**基准四件套**（§2.1）——taskable 项目硬门禁。
5. `roadmap.md` 加「业务线路（<prefix>）」段落（§4，挂账制）。
6. 首个方案（`plans/001-<slug>.md`）→ 转卡 → 首批卡上板。

### 1.3 门禁

- **注册即上页面**：registry 提交后 `GET /projects` 自动包含新项目（无需任何同步）。
- **无基准不出卡**：业务仓缺 AGENTS.md/CLAUDE.md/项目化 README 时，出卡模板会注入「本项目暂无基准文件」提示，机审打回。
- 口头注册 / 手改卡文件 / 手维派生层 = 红线。

## 2. 基准四件套（taskable 项目硬门禁）

| 件 | 位置 | 内容 |
|----|------|------|
| **README**（项目化） | 业务仓根 | 替换脚手架模板：是什么 / 技术栈 / 目录 / 看板入口（§5 指针段） |
| **AGENTS.md** | 业务仓根 | Agent 全局入口：项目定位 + 红线 + **看板指针段**（§5 模板） |
| **CLAUDE.md** | 业务仓根 | 对话式 Agent 入口，引 AGENTS.md，含看板指针段 |
| **首个方案** | `docs/projects/<prefix>/plans/001-*.md` | 项目北极星/首个里程碑，含验收标准与转卡计划 |

> 基准缺失不阻塞注册（注册是 CCC 侧动作），但**阻塞出卡**（§1.3 门禁）。

### 2.2 项目档案七节模板（docs/projects/<prefix>/README.md）

```markdown
# <项目名>（前缀 <prefix>）

## 是什么
<一句话>

## 路径
| 机 | 路径 | 说明 |
|----|------|------|
| M1 / Mac2017 / HP | <registry 同源路径> | M1（中枢）、2017（执行写码/生产）、业务机（业务仓本体写码） |

## 在 CCC 怎么动
出卡前缀 <prefix> · taskable=<Y/N> · 看板 <#/board 入口>

## 基准文件（核心导航 · Agent 必读）
| 文件 | 位置 | 用途 |
|------|------|------|
| 项目档案（本页） | docs/projects/<prefix>/README.md | 注册信息 |
| 方案池 | docs/projects/<prefix>/plans/ | 方案·验收标准 |
| 架构/设计 | <ARCH/设计文档路径，无则 —> | 系统设计 |
| 入口规范 | AGENTS.md / CLAUDE.md（业务仓） | Agent 指引 |

## 线路 / 近况
- ≤3 条

## 禁区
- ≤3 条
```

## 3. 方案与看板（日常开发）

### 3.1 方案（#/plans 方案池）

- 命名：`方案 · <人读标题>`（DOC-PROTOCOL §2.7）；模板 `_template/plan-template.md`。
- 五态流转：草案 → 已确认 → 部分执行 → 已完成 → 作废（DOC-PROTOCOL §2.8）。
- **验收标准必填**（- [ ] 可验证项）；**转卡计划段**决定能拆几张卡。
- 转卡后方案自动推进「部分执行」；收尾时方案/卡双向更新。

### 3.2 任务卡（#/board 看板）

- 只许 `scripts/new-card.sh` 出卡；卡自动带「## 基准文件」节（见卡模板）。
- 卡头「关联」段必须写关联方案编号（`<prefix>-plan-NNN`）；无方案关联的卡机审提示。
- 卡与方案通过「关联」字段双向追踪；收口时方案「已完成」须对应卡「已关闭」。

### 3.3 里程碑方案沉淀（防「只干活不留方案」）

- 任一 taskable 项目累计 ≥5 张已关闭卡后，**必须**补里程碑方案（记录做了什么、怎么做的、验收口径），由下次出卡的中枢检查提示。
- 收口动作：方案「已完成」+ 对应卡全部「已关闭」+ 线路图段落更新。

## 4. 线路图挂账（roadmap.md）

- 每个 taskable 项目注册时在 `roadmap.md` 建「业务线路（<prefix>）」段落（挂账制：一行「未排期」也可，不许缺席）。
- 段落内容：未出卡意向（挂账） + 里程碑（已定稿方案） + 近况。
- 与 `#/roadmap` 页面关系：页面按卡状态聚合展示，文档段落承载意向。

## 5. Agent 入口统一（看板指针段模板）

业务仓 `AGENTS.md` / `CLAUDE.md` 必含以下一段（原文照抄，替换 `<项目名>`/`<prefix>`）：

```markdown
## 项目基准（看板入口）

本项目基准与任务由 CCC 看板统一维护：
- 看板：http://192.168.3.116:7788/#/board（卡状态/派发/验收）
- 方案池：http://192.168.3.116:7788/#/plans（方案与验收标准）
- 项目档案（权威索引）：CCC 仓 docs/projects/<prefix>/README.md
- 出卡/合入一律走任务卡（docs/dispatch/<prefix>/），禁止口头接活
- 开发完成钩子：卡回写时必须填写卡内「## 维护区」四问（方案/教训/README/线路图），未填=机审打回+合入拒绝
```

## 6. 开发完成钩子（Doc-Gate · 2026-08-09 起）

> **背景**：clw001-005 开发完成但方案关联卡没同步、README 近况没更新、零教训沉淀——「开发完成 ≠ 文档完成」。
> **机制**：钩子挂在服务端卡状态机（所有 IDE 回写卡头的唯一交汇点），IDE 无需自建钩子，照常回写即被覆盖。

### 6.1 三环节闭环

```
执行体回写（卡头「已回写」）
  └─▶ 卡内「## 维护区」四问必填（方案同步/教训沉淀/README/线路图）
        │
        ▼
机审（prompt_inject 注入固定检查项）
  维护区缺失或占位 → 机审打回（原因注明缺失项）
        │
        ▼
合入批准（approve-merge.sh 机械门禁 check_maintenance）
  缺维护区/占位 → 拒绝合入
```

### 6.2 维护区四问（new-card.sh 模板自动生成）

| # | 问 | 判定 |
|---|----|------|
| 1 | 方案同步：关联方案状态/关联卡是否已同步？ | [是/否] + 说明 |
| 2 | 教训沉淀：本卡是否产出可复用教训？ | [有/无] + 说明（有 → lessons.md 或 docs/notes/） |
| 3 | 档案/README：是否改变项目结构/技术栈/路径？ | [是/否] + 说明（是 → 项目档案同步） |
| 4 | 线路图：项目近况/下一步是否变化？ | [是/否] + 说明（是 → roadmap/档案「线路/近况」更新） |

### 6.3 维护责任矩阵

| 角色 | 维护内容 | 触发 |
|------|---------|------|
| **执行体**（开发 Agent） | 填维护区四问 + 完成对应文档动作 | 卡回写时（强制） |
| **机审**（机审大模型） | 核对维护区完整性，缺失打回 | 机审阶段（LLM 门禁） |
| **合入批准**（approve-merge.sh） | 机械校验维护区非占位 | 合入时（机械门禁） |
| **Engine** | 方案「关联卡」字段自动同步已关闭卡 | 卡关闭时（自动） |
| **验收席**（Claude Code W1 / Codex W3） | 抽查维护质量（教训是否真实、README 是否准确） | 终验（人工） |

### 6.4 IDE 适配（单一来源）

- **规则正文唯一来源**：qx-map `AGENTS.md`「开发完成钩子」段。
- **Claude Code**：qx-map `.claude/skills/`（机审/验收席自动加载）；各仓 CLAUDE.md。
- **OpenCode**：`~/.config/opencode/`（AGENTS.md + workflow.md）引用 qx-map 钩子段。
- **Codex / Cursor**：workspace rules / .cursorrules 一行指针引 qx-map AGENTS.md，不复制正文。
- **业务仓**：看板指针段含钩子行（§5 模板第 5 行）。

### 6.5 方案「已完成」判定

- 钩子**只做提示**：关联卡全部关闭时提示「可确认完成」；方案「已完成」由老板/验收席按验收标准人工拍板，不自动推进。

## 6. 红线（本项目规范）

1. 注册 = registry + 档案 + 索引表 + 基准四件套 + 线路图段，缺一视同未注册。
2. 禁止手维派生层（种子/kb-seed/硬编码表）——不一致以 registry 为准，不一致就是 bug，报修不改表。
3. 无方案关联的卡、无基准文件的卡 = 流程缺陷，机审打回。
4. 业务仓入口文件（AGENTS/CLAUDE/README）不允许回归脚手架模板。
