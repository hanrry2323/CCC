## 目标

把闲鱼产线从「**技术规格达标即算通过**」升级为「**内容质量可度量、且失败不会伪装成成功**」的自动产线。

一句话判据（可机器验证）：**任一环节产出失败时，产线必须报错而不是报成功；内容质量必须有一个可复现的数字分数，且该分数由机审独立算出、不由产出方自述。**

终点形态：一条 24 小时运行的产线，每日自动出「选题 → 文案 → 视频 → 四平台适配稿」，每份产出带一份**含内容维度的质量分数**与**可复现证据**；低于及格线的不进库、不发布；连续失败的自动熔断并挂人工。

## 一、为什么是 2 分：这不是渲染问题

**先说清楚一件事：渲染本身没有毛病。** 实测链路：PIL 逐帧画 PNG（`scene/generator.py:18-19`，1080×1920 / 30fps）→ ffmpeg 编码（`compose/generator.py`，`-b:v 5000k` + `-nal-hrd cbr` + `-preset slow` + `aacc 192k`）→ **edge-tts 真神经网络配音**（`tts/generator.py` 四音色按情绪标签选：serious=YunjianNeural / humorous=Yunxi / marketing=Xiaoxiao / emotional=Xiaoyi，`SubMaker()` 出 SRT）→ 字幕（FontSize 40 / Outline 2）+ BGM（音量 0.3）。技术规格 9 项全达标。

**2 分的真正来源是三层断链**：

### 断链 1：内容输入是关键词复读（垃圾进）

视频文案由 `video-pipeline/stages/script/generator.py` 的 f-string 模板拼装，模板要读 `data/content-sources.json` 取 `hook`/`title`/`core_selling`——**该文件不存在**（`find` 零命中），于是永远走 fallback，把主题字符串同时塞进三个空位。实测产物 `script.json`（主题「AI视频生成技术原理」）：

- 场景1（28s）：「挑战摆在面前：**AI视频生成技术原理** 很多人卡在这一步。」
- 场景2（26.8s）：「突破来自一个简单但深刻的洞察——**AI视频生成技术原理**。这个思路改变了游戏规则。」
- 场景3（25.2s）：「带来的价值是实实在在的。。如果你也在为**AI视频生成技术原理**头疼，不妨试试这个方案。**一分钱不花，三分钟搞定。**」

`word_count: 119`，3 场景撑 80 秒 = 每秒 1.5 字；主题名复读 3 次；有重复句号「。。」；情绪标签 `humorous` 但文本无任何幽默要素（误判）。

**决定性发现——难的活已经干完了，只是没接线。** 业务仓 `src/xianyu/content/` 里存在完整的 LLM 文案系统：`writer.py`（走 3456 通道写 350 字闲鱼垂类文案，四段结构锁死：3 秒钩子≤2 句 → 痛点场景 → 3 条干货（每条含数字/案例）→ 行动号召；300-400 字自校正，字数超标重生成一次）、`rewriter.py`（一份稿改写为 bilibili 800-1500 字口语化 / toutiao 300-500 字信息流 / weibo 140 字 + #话题# / **video_script = 50-60 秒短视频口播稿**）、`ab_writer.py`（A/B 双版本）、`router.py`（关键词→平台路由）。

**`video-pipeline/` 这条产线与这套 LLM 系统之间零接口。** 实测 `grep "writer\|rewriter" video-pipeline/stages/script/generator.py` 零命中。视频产线缺的正是 `video_script` 口播稿，而它就在隔壁仓库躺着。

### 断链 2：质量门是假的（假验收）

`scripts/check_video_quality.py` 共 11 项，**逐条全是技术规格，零内容质量**：分辨率 / 码率≥3.5Mbps / h264 High Level≥4.0 / 时长 60-90s / 文件大小 / 有 audio stream / srt 非空 / config 有 bgm_path / 5 帧灰度 diff>1.5 / CLIP≥0.25 / cosine<0.70。

**skip 不扣分**——这是最致命的一处（`render_all_templates.py` 的 `parse_quality_json()`）：

```python
fail_count = sum(1 for c in checks if c["ok"] is False)
skip_count = sum(1 for c in checks if c["ok"] is None)
return {"checks": checks, "pass": fail_count == 0, ...}
```

`ok=None` 完全不进 `fail_count`。而第 10、11 项在真实环境**永远返回 `ok=None`**，所以 `pass=True` 实际只证明「9 项技术参数达标」。

**外脑更正子任务自报**：子任务称「sentence-transformers 未装导致永久 skip」。**不实**。本机实测 `python3 -c "import sentence_transformers"` → `INSTALLED 2.7.0`。真因是模型缓存缺失叠加受限网络：`_load_sentence_transformers()`（`check_video_quality.py:362-377`）先以 `local_files_only=True` 加载 `clip-ViT-B-32`，而 `~/.cache/huggingface/hub/` 里只有 `models--BAAI--bge-m3`、**没有 clip-ViT-B-32** → 抛异常 → 回退联网加载 → 失败 → `except: return None`。

**这意味着内容质量检查不是架构死角，是缺一个模型文件 + 缺一行容错。** 唯一能判断「内容对不对题」的检查从未执行过一次。

**人工打分表也从未执行**：`ab-report-20260914-103950/scorecard.md` 四维度（结构/画面/文案适配/整体）分值全是 ` /5` 空值，备注列全空，结论三行（综合最佳模板 / 主要差距 / 后续动作）全空。「人工打分」这一环只交付了空表格。

### 断链 3：失败伪装成成功（污染一切度量）

`src/xianyu/content/video.py:1086-1098` 的 `_write_mock()`：全管线失败时写出一个文本占位文件并 `return` 路径；调用方 `_mock_result()`（:1100-1106）返回 `WorkerResult(success=True)`。

实测后果：`data/videos/` 共 154 个 `.mp4`，其中 **152 个是 47-57 字节的文本占位文件**（hexdump 实证：`[MOCK VIDEO] subject=识别与清理 No image paths`）；`workspace/outputs/video/` 三个任务目录里两个 `final.mp4` 为 **0 字节**，仅一个是真视频。

**这是整个诊断里最重的一条。** 产线跑了很多次，产出几乎全是占位符，而每次都被记为成功。只要这条不改，后面任何质量数字都被假成功污染——**必须先修它，再谈优化**。

## 四、目标架构

四层，每层之间设质量闸，任一闸不过即停在该层不往下传。

```
① 选题层   关键词池/热点 → 选题 → 平台路由(router.py)          ← 新增：选题可追溯
                │
                ▼  [闸 A：选题合法性——红线词/重复选题去重/垂类归属]
② 内容层   writer.py 350字四段 → rewriter.py 四平台稿(含 video_script)  ← 已存在，接通即可
                │
                ▼  [闸 B：内容质量分 —— 见 §五，机审独立算，不出自产出方]
③ 渲染层   口播稿 → 场景 → edge-tts 配音 → PIL 帧 → ffmpeg → 字幕+BGM  ← 现有，无病
                │
                ▼  [闸 C：技术规格 9 项 + 视听一致(CLIP 实跑) + 差异化]
④ 入库层   产物 + 质量分 + 证据包 → 内容库(带指纹/可复现命令)          ← 新增
                │
                ▼  [闸 D：及格线判定 —— 不过不进库；发布仍等 M7/Cookie]
```

**三层职责分离（照搬量化侧已验证的模式）**：产出方（DSH/PI 执行体）→ **不自己打分**；质量席（CC CLI 机审，独立会话零共享上下文，CCC phase2 现成能力）→ 独立复算质量分；调度席（外脑）→ 只看台账与熔断，**永不自验收自己派单**。

## 五、质量度量口径（核心新增，唯一权威定义）

现状：两仓**均无任何 `/100` 或 `2/100` 打分记录**（搜过 CCC `docs/`+`data/`、xianyu 全仓 `*.py/*.md/*.json`、`~/.ccc/data/board-events.jsonl`）。唯一带 `quality_score` 的审计条目是**代码复杂度分**（changed_files / complexity_avg / mypy_errors / assert_per_test），与内容无关。

所以「2 分」是人工主观判断，无记录出处。以下为本方案提出的口径——**首版需实测一次才有基线，本方案不预填分数**（预填即制造假基线，同断链 1 的病）。

| 维度 | 分值 | 判据（机器可算） | 现有能力 |
|---|---|---|---|
| **内容实质** | 30 | 关键词复读率、每段信息密度、是否含数字/案例、字数 300-400 | 需新增；`structural_problems()`/`count_words()` 已有可复用 |
| **结构完整** | 15 | 四段标记齐全、3 秒钩子≤2 句 | `writer.py:97 validate_copy_structure` **已存在** |
| **平台适配** | 15 | 各平台字数区间 + 语气特征词命中 | `rewriter.py` **已存在**，缺判定器 |
| **视听一致** | 15 | CLIP 画面-话题相关度 ≥0.25 | `check_clip_alignment` **已存在**，缺模型文件 |
| **技术规格** | 10 | 现有 9 项 | 已有 |
| **差异化** | 10 | 视频间 cosine <0.70 | `check_uniqueness` 已有，<2 视频时 N/A |

**三条口径铁律（防本方案自己长成断链 2）**：

1. **skip 必须显式可见，禁止静默不扣分。** 改法不是把 skip 直接算 fail（CLIP 模型缺失会让全产线熔断），而是：`pass = (fail_count == 0 AND skip_count == 0)`，同时输出 `pass_partial`（仅 fail 判定）与 `pass_full`（fail+skip 判定）两个字段，入库只认 `pass_full`。口径来源必须能区分「9 项达标」和「11 项全过」。
2. **内容维分数必须由质量席独立算，产出方无权自述。** 产出方回执里的质量分一律不采信，以闸 B 机审复算值为准。
3. **分数必须随句标口径**（引擎版本 / 模型版本 / 样本段 / 是否全量），单窗观察不构成过门证据——照搬量化侧 `caliber-authority-spec` 的模式。

**及格线建议：60 分**（内容实质 ≥18/30 + 结构满分 + 平台适配 ≥9/15 + 技术规格满分）。**目标线 75 分。** 低于及格线不进库。

> ⚠️ 此建议待 §八 拍板点 2 确认。

### §五之二 防乐观评分（老板 2026-09-18 明令，8 条机器可判）

**老板原话：「可以用，但是必须防止乐观评分。」** 本方案自身就长着乐观偏病的标本——§一断链 2 里 `pass=True` 只证明 9 项达标、`_write_mock()` 把失败标记为成功。**评分系统若不做防乐观设计，就是第四个断链。**

以下 8 条每条都写成可机器判定的断言（不是「注意不要乐观」这类无法验收的软要求），全部由阶段 1 的质量席位单测覆盖：

| # | 条款 | 机器可判断言 |
|---|---|---|
| 1 | **skip 永不静默通过** | `pass_full` 必须 = `(fail==0 AND skip==0)`；有 skip 时 `pass_full` 恒 False。测试：构造 1 项 skip 的输入，断言 `pass_full is False` 且 `skip_names` 非空 |
| 2 | **禁总分单出** | 任何输出含总分时必须同出 6 维分项 + 口径标注；缺分项或口径则拒绝落盘。测试：缺口径的打分结果写入必须抛错 |
| 3 | **首版基线禁锚定主观值** | 首版基线的 `baseline_source` 必须是 `measured`，禁止 `anchor_from_prior`；基线节在首次实测前必须为空。测试：断言首版落库记录 `source=="measured"` 且不含任何硬编码初始分 |
| 4 | **内容分禁产出方自述** | 分数来源字段必须是 `quality_seat`（质量席独立算）；来源为 `producer`/`self_report` 一律拒收。测试：伪造产出方自报分的信封，断言被拒 |
| 5 | **单窗不作过门证据** | 样本数 < 10 或样本同源（同主题/同模板）时，输出 `pass_gate=False` 并标 `insufficient_sample`；禁止在样本不足时输出「已达标」 |
| 6 | **提升须双侧同时测** | 报「提升」时必须同时给改动前后的样本数、口径与差值，且两组样本集有交集（否则不可比）。测试：报提升但两组样本不相交 → 判无效 |
| 7 | **异常值当疑似 bug** | 分数 ≥90 或环比提升 >30 分时，强制标 `suspect_outlier` 并触发人工复核，不得直接计为达标。测试：构造 95 分样本，断言带 outlier 标记 |
| 8 | **失败不降级为通过** | 产出方回执含失败信号（`success=False` / 产物为 0 字节 / 产物为文本占位）时，质量席位禁止给出任何分数，只能标 `no_artifact`。测试：0 字节 mp4 输入，断言返回 `no_artifact` 而非 0 分或任意分数 |

**为什么第 8 条最重要**：本仓已有两处乐观偏病实锤——`_write_mock()` 把失败标成 `success=True`（152/154 假视频），`pass=True` 把「只验了 9 项」说成「全部通过」。评分系统若照搬这套语义，会在错误的分母上打出漂亮分数。**先立「无产物不给分」，再谈分数怎么算。**

**评分系统自身的验收口径**：上述 8 条每条必须有一个失败测试（输入故意违反条款，断言被拒绝）。**8 条全绿是阶段 1 的前置**——没有这 8 个测试，阶段 1 产出的任何基线分数一律不采信。

**首版真实基线分数**：待阶段 1 实测，本方案不预填。老板的「2 分」是主观失望评分（老板 2026-09-18 明说），**不是测量值，不入任何口径计算**，仅作背景注记保留。
