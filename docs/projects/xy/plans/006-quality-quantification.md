## 目标

把 `VIDEO_QUALITY_DEV_PLAN.md` 的质量量化路线真正落地成可执行、可验收的标准——码率 ≥3.5 Mbps、文件 ≥9 MB、时长 60-90s、1080×1920 竖屏、含配音/字幕/BGM/动态镜头，并用 `check_video_quality.py` 产出可复现的质量报告。

## 背景

质量一期已交付（码率 0.12→3.7 Mbps、文件 4.72→26.52 MB、A1-A6 全达），compose 已用 CBR 5Mbps 高码率（实测 4.97 Mbps 达标）。但：`samples/` 目前为空（摸底确认「空 — 等待用户上传」），`check_video_quality.py` 无真实样片可测；质量量化标准散在 `VIDEO_QUALITY_DEV_PLAN.md` 里，未固化成自动化验收门。M3 高表现力需要「质量可量化、可回归」——否则样片好坏全靠人眼，无法进 CCC 验收。

## 方案内容

三块：

1. **质量基线工具**：`check_video_quality.py` 跑通，输出结构化质量报告（码率/文件大小/时长/分辨率/含配音/字幕/BGM/动态镜头），作为验收证据。
2. **编码参数对齐**：对照量化标准（码率 ≥3.5 Mbps、文件 ≥9 MB、时长 60-90s、1080×1920、AAC 192k 等）核实并锁定 compose 编码参数（`VIDEO_QUALITY_DEV_PLAN.md` F1 已 CBR 5Mbps，核对其余项）。
3. **样片交付**：产 3 条真实样片入库 `samples/`，全量化达标，作为 M3 高表现力的可验收成果。

## 验收标准

- [ ] `check_video_quality.py` 对每条样片输出结构化质量报告，可复现
- [ ] ≥3 条样片全量化达标（码率 ≥3.5 Mbps / 文件 ≥9 MB / 时长 60-90s / 1080×1920 / 含配音/字幕/BGM/动态镜头）
- [ ] 编码参数锁定并有文档记录（`VIDEO_QUALITY_DEV_PLAN.md` 落地）
- [ ] 样片入库 `samples/`，供后续渲染升级（3.3）对比基线

## 功能卡

### 质量基线工具跑通

目标：`check_video_quality.py` 输出结构化质量报告。

实现：核实 `check_video_quality.py` 现状（摸底提到「需真实生产视频入库供基线重测」）；补全缺失检测项（配音/字幕/BGM/动态镜头存在性）；输出 JSON/Markdown 报告。

验收：对任一样片执行可输出完整质量报告，各检测项有值。

颗粒度：工具完善 + 报告格式，单模块。

依赖：无

架构位置：质量基线工具（check_video_quality.py）

### 编码参数对齐

目标：compose 编码参数对照量化标准锁定。

实现：按 `VIDEO_QUALITY_DEV_PLAN.md` 量化标准逐项核对 compose（`video-pipeline/stages/compose/`）编码参数：码率（已 CBR 5Mbps）、分辨率（1080×1440 现状 vs 目标 1080×1920）、音频（AAC 192k）、时长控制、动态镜头；不一致项修正。

验收：编码参数与标准逐项一致，参数变化有文档记录。

颗粒度：参数核对 + 修正，单模块。

依赖：无

架构位置：video-pipeline compose 编码阶段

### 样片交付与基线入库

目标：3 条真实样片入库 `samples/`，全量化达标。

实现：用已锁定的模板 + 编码参数产 3 条不同内容/风格的样片；`check_video_quality.py` 逐条跑质量报告确认达标；样片入库 `samples/`。

验收：3 条样片质量报告全达标，`samples/` 有真实产物。

颗粒度：样片生产 + 基线验证，多文件产出。

依赖：质量基线工具跑通, 编码参数对齐

架构位置：视频生产 + 质量基线
