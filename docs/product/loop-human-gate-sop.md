# Loop 人审闸门 SOP（只审不投 · 螺旋开发）

> **定位**：Loop Observer（后台审）产出 → 运维看板 → **人审闸门** → 转待办。防止「机器自己审自己投」的自激循环。
> **核心**：Loop Agent 只负责审，产出物**不能直接进待办**，必须经过老板 + IDE 工具重新评判后才转开发。
> **依据**：老板 2026-08-11 定调 + ENGINEERING-CANON + ccc-plan-011（Loop Observer）。
> **状态**：v1 定稿 · 更新：2026-08-11

---

## 一、三层审的分工

| 环节 | 时机 | 审什么 | 谁判 | 输出 |
|------|------|--------|------|------|
| **机审** | 单卡回写后 | 本次质量/红线/规范 | LLM（异席） | 通过/打回（可执行原因） |
| **审核** | 阶段结束/版本前 | 整体一致性/回归/交付物 | 老板/验收席 | 阶段验收报告 |
| **Loop（后台）** | 持续 | 已回写项目 vs 线路图/文档漂移 | Loop Agent（**只审不投**） | 运维看板产出 |

---

## 二、Loop 产出流向（固定）

```
Loop Observer 后台运行（scheduler）
  → 产出巡查报告（DATA_DIR/observer/*.md + docs/notes/*-patrol.md）
  → 运维看板展示（GET /loop/findings，含发现 + 建议出卡命令）
  → 【人审闸门】老板 + IDE 评估：
       ① 采纳 → 执行建议命令转卡（new-card.sh --related "patrol: <报告>"）
       ② 不采纳 → 留档（记录原因），不转开发
       ③ 待定 → 留运维看板，后续再评
  → 转待办 → 进入开发 → 机审 → 审核 → 回到 Loop
  ↑____________________ 螺旋上升 ____________________
```

---

## 三、人审闸门规则（硬）

1. **Loop 只审不投**：observer 只打印建议出卡命令，**绝不自动执行**（代码层已保证）。
2. **人审是唯一转卡通道**：运维看板产出 → 老板/IDE 评估 → 采纳才转卡。无人工确认 = 永远不转开发。
3. **评估维度**：
   - 发现是否真实（对照代码/文档复核，防幻觉）
   - 优先级（权重分高/影响面大 → 优先）
   - 是否符合当前开发方向（对齐线路图）
4. **转卡规范**：用建议命令转卡（`--related "patrol: <报告名>"` 留痕追溯），卡走正常流程（待分派→开发→机审→审核）。
5. **不采纳留档**：记录原因（不是所有 Loop 发现都要转卡，有些是信息/低优先）。

## 四、运维看板类目（固定落点）

- **端点**：`GET /loop/findings`（2017 :7788）
- **内容**：最新 10 份巡查报告，每份含发现 head + 建议命令
- **入口**：运维界面 → Loop 类目（展示报告 + 建议卡，不自动投）
- **数据源**：`DATA_DIR/observer/*.md`（observer.py 生成）

---

## 五、螺旋开发循环（全景）

```
基础开发（老板定意图 → IDE 拆卡 → 执行 → 机审 → 收卡）
   + 后台 Loop（对照线路图/文档 持续审查已回写项目）
   = 螺旋上升：每一轮都在前一轮基础上优化
```

- **被动 Loop**：后台 Agent 驱动审查，产出进运维看板
- **主动开发**：老板/IDE 基于人审结果定下一步方案
- **循环**：开发 → Loop 审 → 人审 → 再开发
