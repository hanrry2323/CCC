# 卡作者手册（一页）

> 定位：写任务卡的正确姿势。出卡唯一入口 `scripts/new-card.sh`，本文是它的「怎么填不废卡」说明。
> 对照 `DOC-PROTOCOL.md §2`（命名定死）+ `card-hub-manual.md`（制卡发卡）。所有路径相对主仓根。

## 0. 一句话

卡是「给执行体的一次性订单」。**范围节只写文件路径、段名对齐 card_gate、维护区四问必须能答**。违反这三条 = validate 红 / 机审打回。

## 1. 出卡（两种）

```bash
# 默认骨架卡（占位正文，执行体实现前补齐）
scripts/new-card.sh --project <prefix> --title "…"

# -f 内容文件一次成卡（正文/步骤/验收全部先写好）
scripts/new-card.sh --project <prefix> --id <prefix>NNN-<slug> -f ./card-content.md
```

`-f` 时：首行须 `# 任务卡 <ID> · <标题>`；标题/卡号从首行解析；必须配 `--id`（防正文/文件名漂移）。仍走编号查重 → 索引刷新 → validate → 原子 commit+push。

## 2. 范围节（废卡头号原因）

- **每行一个纯相对路径**，指向主仓内真实存在的文件/目录。
- 禁自然语言说明、禁绝对路径、禁反引号包路径、禁序号前缀。
- 只列「本卡会改动/读取的路径」；业务仓文件用 `## 基准文件` 节自然语言提及，不进范围节。

```markdown
## 范围

docs/dispatch/tst/tst905-smoke-newcard-f.md
```

## 3. 段名对齐 card_gate

`card_gate` 校验按这些段名识别，写错即「缺必备段」废卡：

`目标` · `实现要求` · `红线` · `范围` · `步骤` · `验收标准` · `门禁` · `回写要求` · `维护区`

- `验收标准`：≥1 条可核条目（命令 + 期望输出）。
- `门禁`：测试/编译/lint 三行，无则留空；`范围：false` 表示范围白名单不用自动核对。
- `步骤`：每步可验证；收尾「卡头改已回写」由引擎代做（新链路，见 §5），卡里写明「写 .ccc-result.md 后停手」。

## 4. 维护区四问（完成钩子）

回写时四问逐项 `[是/否][有/无]` + 说明，禁止占位。缺失/占位 = 机审打回 + 合入拒绝。

1. 方案同步：关联方案状态/关联卡是否同步？
2. 教训沉淀：本卡是否产出可复用教训？
3. 档案/README：是否改变项目结构/技术栈/路径？
4. 线路图：项目近况/下一步是否变化？

## 5. A1/A2 新链路（2026-09-03 起）

- 执行体只在 worktree 干活，收尾写 `.ccc-result.md`（标题复述/探针/自测/四问/变更证据），**不直接改主仓卡**。
- 引擎收单后读结果文件，代写主仓卡回写区/维护区四问/卡头「已回写」并原子推送。
- 所以卡里**不要**写「执行体直接改卡头状态/填回写区」——那是旧链路；新链路写「写 .ccc-result.md 后停手」。

## 6. 常见废卡原因（三条实锤）

| 原因 | 实锤 | 正确做法 |
|------|------|----------|
| 范围节写自然语言/绝对路径 | tst900/tst901 被 card_gate「范围路径不存在」作废 | 范围节每行一个纯相对路径 |
| 回写区空/占位 | tst902 收单后回写区仍空 → 机审门禁拦 | 确保执行体产出结果文件（新链路）或回写区真实填写（旧链路） |
| 卡头状态非法值 | 写 `completed`/`done` 英文 | 只写中文合法态：待分派/执行中/已回写/打回/已关闭/作废 |
