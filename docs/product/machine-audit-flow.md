# 机审流程（2017 自动 · 看板「机审」栏）

> **状态：现行 · 2026-08-06**  
> 卡头仍是五态；看板多一列 **机审**（派生）：`已回写` 且尚无 `## 机审区` 通过 → 落入「机审」栏。  
> 终验：[`accept-board-sop.md`](accept-board-sop.md)

## 流程怎么走

```text
出卡（待分派）
  → Engine 派 OpenCode（执行中）
  → 机械门禁通过 → 卡头改「已回写」
  → 看板落入「机审」栏（尚无机审通过）
  → Engine 自动拉卡头「验收」方（默认 Claude）写 ## 机审区
  → 机审：通过 → 仍「已回写」，看板进「已回写」栏（可终验）
  → 机审：不通过 → 打回 → 待分派再派开发
  → 老板说「验收看板」→ ## 验收区 + 已关闭
```

| 看板列 | 卡头状态 | 条件 |
|--------|----------|------|
| 待分派 | 待分派 | — |
| 执行中 | 执行中 | — |
| **机审** | 已回写 | **无** `机审：通过` |
| 已回写 | 已回写 | **有** `机审：通过`（等人终验） |
| 已关闭 | 已关闭 | — |
| 打回 | 打回 | — |

## 文档怎么写（卡内）

1. **开发执行体**：卡头 → `已回写`；填回写区；**禁止**写 `## 机审区` / `## 验收区` / `已关闭`。  
2. **机审席（Engine 自动）**：在**生产卡绝对路径**追加：

```markdown
## 机审区

机审：通过
证据：…（git log/diff / 对照验收标准）
```

失败写 `机审：不通过` + 清单，进程非 0。  
3. **终验（M1「验收看板」）**：只处理「已回写」栏（机审已过）的卡 → `## 验收区` + `已关闭`。

## 实现要点（防踩坑）

- 机审常在 worktree 改卡副本；Engine 必须把 `## 机审区` **同步回生产卡路径**再判定通过（否则会误打回）。  
- 注册表验收席须为「可后台 CLI」+ 机审参数模板（见 `executors.example.json`）。  
- 卡头五态不变；「机审」只是看板派生列。
