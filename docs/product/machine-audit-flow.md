# 机审流程（2017 自动 · 看板「机审」栏）

> **状态：现行 · 2026-09-04**
> 卡头仍是五态；看板多一列 **机审**（派生）：`已回写` 且尚无 `## 机审区` 通过 → 落入「机审」栏。  
> **机审通过 = 质量过**。合入主链为 **phase2 一段式**（后段 CC CLI：审核→合入→部署→已关闭）；下文「机审栏 → 人审合入批准」两段式为史（保留供追溯，2026-09-04 批B标注）。

## 流程怎么走

```text
出卡（待分派）
  → Engine 派执行会话（执行中）
  → 机械门禁通过 → 卡头改「已回写」
  → 看板落入「机审」栏（尚无机审通过）
  → Engine 自动拉卡头「验收」方写 ## 机审区
  → 机审：通过 → 仍「已回写」，看板进「已回写」栏 = ready_for_merge
  → 机审：不通过 → 打回 → 待分派再派开发
  → phase2 CC CLI（后段）自动审核/验收/合入/部署 → 已关闭
```

**现行主链（phase2 一段式）**：`已回写 → phase2 CC CLI 审核→合入→部署 → 已关闭`。两段式「机审栏 → 老板审 diff → 人工「合入批准」→ 已关闭」为史。

| 看板列 | 卡头状态 | 条件 |
|--------|----------|------|
| 待分派 | 待分派 | — |
| 执行中 | 执行中 | — |
| **机审** | 已回写 | **无** `机审：通过` |
| 已回写 | 已回写 | **有** `机审：通过`（可合入批准） |
| 已关闭 | 已关闭 | — |
| 打回 | 打回 | — |

## 文档怎么写（卡内）

1. **开发执行体**：卡头 → `已回写`；填回写区；**禁止**写 `## 机审区` / `## 验收区` / `已关闭`。  
2. **机审席（Engine 自动）**：在**生产卡绝对路径**追加：

```markdown
## 机审区

机审：通过
证据：…（git log/diff / 对照验收标准）
```

失败写 `机审：不通过` + 清单，进程非 0。  
3. **phase2 CC CLI（后段，现行主链）**：只处理「已回写」栏 / `ready_for_merge` → `approve-merge.sh`（写验收区 + 已关闭）。两段式的「人审合入批准」为史（人工兜底/否决仍走同一入口）。

## 实现要点（防踩坑）

- 机审常在 worktree 改卡副本；Engine 必须把 `## 机审区` **同步回生产卡路径**再判定通过（否则会误打回）。  
- 注册表验收席须为「可后台 CLI」+ 机审参数模板（现役绑定见 `executors.example.json`；注册表只写角色语义，工具绑定以 executors.json 为准）。
- 卡头五态不变；「机审」只是看板派生列。

## 代理易错（终验前必读）

1. **回写真值在分支**：开发回写常先落在 `codex/<卡文件名去.md>`；`main` 未合入前，M1 本机 `docs/dispatch` 卡头可能仍是「待分派」。  
   - **进度以** 2017 `:7788` `/board/snapshot`（看板列）**或** 分支 tip 为准，不以未 `fetch` 的本地 main 卡头为准。  
   - 终验取证：`git fetch origin codex/<stem>` → `git diff origin/main...origin/codex/<stem>`（见 [`accept-board-sop.md`](accept-board-sop.md) §0）。  
2. **五态 ≠ 看板列**：`/board/states` 顶层「已回写」= 卡头基础态计数（含仍在「机审」列的卡）；真正可终验看 `columns.已回写` 或 snapshot「已回写」列。  
3. **机审只属 2017 Engine**：M1 听到「验收*」走终验 SOP，**禁止**代写 `## 机审区`。机审通过后正文须在**将要终验的那份卡**（生产路径 / 已同步内容）可见。

## 实现要点（2026-08-24 直修增补 · 防踩坑）

- **标记命名分流**：机审阶段 refresh 按 phase 写 `{id}-audit.running`，与认领/finally 清理同名；plain `{id}.running` 仅执行阶段使用。
- **判活口径**：只认工作者 PID（`pid=`/`child_pid=`），恒活 `engine_pid=` 不计入（`_parse_running_marker_worker_pids`）；web/exec_metrics 同源语义。
- **强拆时距**：`_effective_max_marker_age()`=1.5×EXECUTOR_TIMEOUT（机审标记再收紧至 2×机审超时）；超时/-9/-15 失败归 infra 特征，不烧业务重试预算。
- **熔断台账**：所有强制击杀路径统一 `_record_force_kill(data_dir=cfg)` 入 `DATA_DIR/force_kill_ledger.json`；同卡 24h≥3 次 → 停自动派发并落 alerts 告警文件（人工删除恢复）。台账必须透传 data_dir——缺省回退曾致测试污染生产（w4/ret1/ret2 事故）。
- **单实例锁**：engine 启动取 `DATA_DIR/engine.lock` fcntl 排他锁，双开退出码 2。
- **回收口 killpg 全覆盖**：reclaim 强拆支路/常规回收支路/cleanup 兜底/claim 覆写前四处均先按进程组收割幸存者。
