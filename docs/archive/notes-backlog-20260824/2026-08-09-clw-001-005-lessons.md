## 教训

### 1. 卡头「关联」段格式必须统一（流程）

- **现象**：clw003/004/005 关联段写 `ccc-plan: clw003 侧边栏…`（人读标题），clw002 写 `clw-plan-001 · 阶段 2/6`（标准格式）——两套并存。
- **根因**：无强制校验，执行体各写各的。
- **规则**：关联段必须 `关联：<prefix>-plan-NNN · 阶段 x/N`（或「阶段外补丁」）；方案编号为准，禁止写人读标题代替。
- **落地**：已修 clw003/004/005/007 卡头；出卡模板即标准格式，勿改。

### 2. 开发完成 ≠ 文档完成（流程）

- **现象**：clw001-005 全部「已关闭」，但方案 001 关联卡只写 clw001；README 近况停留在「6 张卡待出」；零教训沉淀。
- **根因**：卡状态机只管代码合入，没有文档收口环节。
- **规则**：完成钩子（Doc-Gate）——回写必填维护区四问（方案同步/教训/README/线路图），机审打回 + 合入拒绝。规范见 CCC `docs/projects/onboarding.md` §6。

### 3. 方案「关联卡」应随卡关闭即时补录（流程）

- **现象**：方案只记首批卡，后续卡关闭后无人回填。
- **规则**：每卡回写时同步方案「关联卡」字段（Engine 卡关闭后也自动追加）。

### 4. 首批卡验收执行体混用（流程）

- **现象**：clw001/002 验收=Claude Code（异席），clw003-005 验收=OpenCode（同席）。
- **规则**：验收默认异席（Claude Code / Codex），同席验收须老板点名；见 qx-map `ide/tool-roles.md`。
