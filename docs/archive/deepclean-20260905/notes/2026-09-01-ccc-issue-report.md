# CCC 问题情况说明

> 日期：2026-09-01
> 范围：仅 CCC 平台本身
> 依据：2017 生产进程、运行日志、健康报告与 CCC 仓库状态的只读核验

## 一、总体判断

CCC 当前服务进程在线，Engine 持续运行，代码仓 `main` 与 `origin/main` 对齐；但运行配置、状态识别和健康探活存在不一致，当前不能判定为完全健康。

## 二、已核实问题

### 1. Engine 持续报告已退役 Relay 配置缺失

- **现象**：Engine 日志反复出现 `missing required config keys: RELAY_PORT, RELAY_UPSTREAM_URL`。
- **证据**：`/Users/fan/.ccc/logs/engine.stderr.log:1-15`。
- **影响**：Engine 虽能继续进入持续模式，但运行配置仍引用已退役 Relay 的必填项，导致日志持续报错，并使配置健康性无法明确判定。
- **当前事实**：当前模型出口已不是旧 Relay；但 Engine 启动配置与现行出口口径没有完全收敛。

### 2. Engine 对作废状态卡持续产生未知状态告警

- **现象**：Engine 多次提示跳过 `ccc075`、`tst003`，原因是状态为 `已作废`。
- **证据**：`/Users/fan/.ccc/logs/engine.stderr.log:18-33` 及后续重复记录。
- **影响**：作废卡虽然被跳过，不会进入正常派发，但 Engine 运行时状态识别与当前卡状态枚举不一致，造成持续噪声，并可能掩盖真实状态异常。
- **当前事实**：CCC 代码侧已声明支持作废状态，但运行日志仍按旧状态集合处理，代码与运行版本/配置存在待对齐问题。

### 3. 生产健康检查的 Web 探活地址与实际监听地址不一致

- **现象**：生产健康报告记录 `web:7788 000`，而实际 Web 服务绑定 `192.168.3.116:7788`，该地址可返回 HTTP 200。
- **证据**：`/Users/fan/.ccc/logs/prod-health-20260901.md:7-9`；本次只读探活结果为 `192.168.3.116:7788/health` HTTP 200；监听进程为 `/Users/fan/program/CCC/server.web.server`。
- **影响**：健康报告可能误报 Web 服务不可用，降低故障判断和自动巡检的可信度。
- **当前事实**：服务本身在线，问题在探活目标地址口径未与实际绑定地址统一。

### 4. 看板实时状态缺少可用的当前证据

- **现象**：本地 `board-live.md` 最后生成于 2026-08-31 21:03，显示卡总数为 0；当前看板敏感接口需要鉴权，未能从本次只读会话取得实时卡列表。
- **证据**：`/Users/fan/qx-map/sync/board-live.md:2-5`；当前 CCC 看板接口未携带会话凭据时返回 HTTP 401。
- **影响**：不能依据过期快照判断当前卡数量、待派发、执行中或待合入状态；看板作为流程真值源的可观测性不足。
- **当前事实**：Engine 运行指标显示最近 `dispatched=0`、`in_flight=0`、`audit_in_flight=0`，但这不能替代实时看板卡状态。

## 三、当前运行状态

- CCC Web 健康端点：HTTP 200。
- CCC Engine：持续运行，`engine-pipeline.json` 的 `ok=true`。
- 最近运行指标：执行池与机审池均无占用，无超时、无失败。
- 代码仓：工作树干净，`main` 与 `origin/main` 对齐。

## 四、结论

CCC 目前属于"服务在线、空闲运行、基础功能可用，但运行面存在配置和观测口径不一致"的状态。上述问题不表现为当前服务立即中断，却会影响 Engine 日志可信度、状态识别一致性和看板判断，需后续按 CCC 自身维护流程处理。

## 五、外脑复核结论（09-02）

> 追加日期：2026-09-02 · 依据：09-02 基线调研实测（复现命令见 `docs/notes/2026-09-02-ccc-baseline-survey.md`）。本节对前述四项作口径修正。

### 5.1 探活 000：绑定口径问题，非故障（修正）
- 实测：`curl 127.0.0.1:7788/health` → `000`（拒绝连接）；`curl 192.168.3.116:7788/health` → `200`。
- 定性修正为：服务在役且健康，仅因 08-30 起 web-server 改绑内网地址 `192.168.3.116:7788`（plist ProgramArguments `--host 192.168.3.116`），127.0.0.1 不再监听。**探活目标是探活脚本/巡检的口径问题，非服务故障**。

### 5.2 前两项告警：按「生产运行体未对齐」口径修正定性（修正）
- **Relay 缺失告警**：`[FATAL] missing required config keys: RELAY_PORT, RELAY_UPSTREAM_URL` 仅存在于 `engine.stderr.log` 文件头部 15 行，属 08-30 01:47 重启之前的旧运行段（该日志自 08-03 持续追加）；现行 engine（08-30 01:47 起 PID 80288）启动后已不再产生该告警。源码侧 `server/config/loader.py:30` 已注明 RELAY 自 2026-08-24 中转站退役后从必填移除。
- **作废状态告警**：`跳过未知状态卡: id=ccc075/tst003` 全部 1634 次（817×2）均出现在最后一次 `Engine 持续模式启动`（日志行 51347，即 08-30 01:47 重启）之前；重启后零告警。源码侧 `server/engine/store.py:50-52` 已有「已作废→VOIDED」归一映射（2026-08-24 直修）。
- 综合修正为：两告警 = 旧运行期日志残留片段 + 运行体未随源码更新（08-30 重启前），**当前生产运行体已与源码对齐，两项告警均已消停**；原报告按日志文件头部旧段误判为"持续出现"，特此更正。

### 5.3 范围表述修正（原报告引用了 qx-map 内容）
- 原报告 §二.4 引用了 `/Users/fan/qx-map/sync/board-live.md`（qx-map 运营侧/外部轨道的产出物），与文首"范围：仅 CCC 平台本身"的声明不符。
- 修正口径：该引用仅作为看板快照的佐证材料，**不构成 CCC 平台自身运行状态**；看板实时状态应以 CCC 看板 API（POST /session 换 token 后 GET /board/*）为准。qx-map 侧产物属另一轨道，不在本报告的定性与修复范围内。

### 5.4 看板 401 复核（不变更，仅补充）
- 复核确认：无凭据访问看板读端点一律 401 系 2026-08-29 P1 收口的**设计行为**（`server/web/server.py` 读闸全量入闸，`_NO_AUTH_PATHS` 仅豁免 `/health /session /config /projects`），非鉴权配置故障。
