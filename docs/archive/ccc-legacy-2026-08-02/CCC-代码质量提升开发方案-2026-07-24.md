```yaml
      - uses: actions/checkout@v4

        with:
          python-version: "3.12"

      - name: Run pre-commit

          if [ -f .pre-commit-config.yaml ]; then
            pre-commit run --all-files

          fi

  precommit:
    name: pre-commit (强制执行 5 hooks)
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Verify config exists
        run: |

      - name: Run pre-commit (all files, all hooks)
        run: pre-commit run --all-files --show-diff-on-failure
```

### 2.2 废除 `ccc_board.ROOT` 猴子补丁全局

**问题**：[engine/workspace.py:28-31](file:///Users/apple/program/CCC/scripts/engine/workspace.py#L28-L31) 的 `_activate_workspace` 通过修改模块全局 `ccc_board.ROOT` / `ccc_board.BOARD` 切换 workspace。20 处调用点。`ThreadPoolExecutor` 并发读全局 = 跨 workspace 污染面。

**策略**：**所有 API 改为显式传 `ws` / `store` 参数**，分 3 步走：

#### 步骤 1：在 `engine/workspace.py` 新增 `WorkspaceContext` 类

```python
# engine/workspace.py 新增

from contextlib import contextmanager
from pathlib import Path
from threading import local
from _board_store import FileBoardStore

_thread_local = local()


@dataclass
class WorkspaceContext:
    """替代 ccc_board.ROOT 全局的线程安全 workspace 上下文。"""
    ws: Path
    store: FileBoardStore


def get_current_workspace() -> WorkspaceContext | None:
    """获取当前线程的 workspace 上下文（替代 ccc_board.ROOT）。"""
    return getattr(_thread_local, "ctx", None)


@contextmanager
def workspace_scope(ws: Path):
    """线程级 workspace 上下文管理器。

    用法：
        with workspace_scope(ws):
            # 在此 block 内，get_current_workspace() 返回 ws
            dev_role_launch(tid)
    """
    store = FileBoardStore(ws)
    _thread_local.ctx = WorkspaceContext(ws=ws, store=store)
    try:
        yield
    finally:
        _thread_local.ctx = None
```

#### 步骤 2：逐个替换 `_activate_workspace(ws)` 调用

```python
# 改前（ccc-engine.py 20 处）

dev_role_launch(tid)

# 改后
with workspace_scope(ws):
    dev_role_launch(tid)
```

#### 步骤 3：board/roles/ 内部改用 `get_current_workspace()`

```python
# 改前（board/roles/dev.py）
def dev_role_launch(tid: str):
    ws = ccc_board.ROOT  # 读全局
    store = ccc_board.BOARD  # 读全局

def dev_role_launch(tid: str):

        raise RuntimeError("dev_role_launch called outside workspace_scope")
    ws = ctx.ws
```

**修改文件**：[engine/failure_router.py](file:///Users/apple/program/CCC/scripts/engine/failure_router.py)（阶段 1 新建）

```python
# engine/failure_router.py

# 统一重试预算：单卡总重试次数上限（跨 product/review/hang/phase 各层）
MAX_TASK_RETRY_BUDGET = 8

# task JSONL schema 新增字段：retry_count
# 每次任何层触发重试时，调用 increment_retry_count(ws, tid)

def increment_retry_count(ws: Path, tid: str, store: FileBoardStore) -> int:
    """递增 task 的重试计数器，返回新值。

    超过 MAX_TASK_RETRY_BUDGET 时抛 RetryBudgetExceeded。
    """
    col, task = store.find_task(tid)
    if not task:
        raise ValueError(f"task {tid} not found")

    current = task.get("retry_count", 0)
    new_count = current + 1

    if new_count > MAX_TASK_RETRY_BUDGET:
        raise RetryBudgetExceeded(
            f"task {tid} retry budget exceeded: {new_count}/{MAX_TASK_RETRY_BUDGET}"
        )

    # 更新 task JSONL
    task["retry_count"] = new_count
    store.update_task(tid, col, task)
    return new_count


class RetryBudgetExceeded(Exception):
    """单卡重试预算耗尽。"""
```

```python
    return None
```

### 3.2 新增红线 R-16：新代码必须带类型提示 + 单测 + docstring

**修改文件**：[references/red-lines.md](file:///Users/apple/program/CCC/references/red-lines.md)

```markdown
## R-16：新代码三件套（type hints + smoke test + docstring）

**规则**：新增模块或新公开函数（非 private `_` 前缀）必须同时存在：
1. **Type hints**：def 行有完整的参数类型 + 返回值类型注解
2. **Smoke test**：tests/scripts/ 下有对应的 test 文件（至少 1 个 test case）
3. **Docstring**：说明入参、出参、异常、副作用

**Why**：无类型 = mypy 永远翻绿不了；无测试 = 回归挡不住；无 docstring = Agent 不知道怎么用。

**触犯后果**：Critical — 直接 revert，不计入进度。

**检查方式**：
- pre-commit hook 自动检查（新增 `scripts/precommit-new-code-quality.sh`）
- Code review 时 reviewer 确认

**例外**：
- `__init__.py` 的 re-export 不需要 docstring
- 测试辅助函数不需要 type hints（但要有 docstring 说明用途）
```

**核心代码**（`scripts/precommit-new-code-quality.sh`）：

```bash
#!/usr/bin/env bash
# precommit-new-code-quality.sh — R-16: 新代码三件套检查
# 检查 git diff 中新增的公开函数是否有 type hints + docstring

set -euo pipefail

# 获取 staged 的新增 .py 文件
STAGED=$(git diff --cached --name-only --diff-filter=A | grep '\.py$' || true)
if [ -z "$STAGED" ]; then
    exit 0
fi

VIOLATIONS=0

for f in $STAGED; do
    # 检查公开函数（非 _ 前缀）是否有 type hints
    while IFS= read -r line; do
        # 提取函数名
        func_name=$(echo "$line" | grep -oP 'def \K[a-zA-Z_][a-zA-Z0-9_]*')
        if [ -z "$func_name" ]; then
            continue
        fi
        # 跳过 private
        if [[ "$func_name" == _* ]]; then
            continue
        fi
        # 检查是否有 -> 返回值注解
        if ! echo "$line" | grep -q '-> '; then
            echo "R-16 VIOLATION: $f: function '$func_name' missing return type hint"
            VIOLATIONS=$((VIOLATIONS + 1))
        fi
    done < <(grep -n '^def \|^    def ' "$f" || true)
done

if [ "$VIOLATIONS" -gt 0 ]; then
    echo "R-16: $VIOLATIONS violations found. Add type hints or prefix with _ if private."
    exit 1
fi
```
