# 7788 对话页（HTTP 端）优化评估 — 2026-08-01

> 定位：http://192.168.3.140:7788/#/chat 与桌面端 App 同一业务链（浏览器/Desktop → 7788 sidecar → M1 loop-router → 上游模型）。

## 一句话结论

功能底座不差、体验欠打磨、安全有隐患。前端已是最新（A 系列修复在 7788 直接生效，静态文件磁盘直读），但「对话壳特有体验」和「运维/看板在对话壳下的使用」没专项优化过；对话口鉴权默认值代码与注释矛盾，需先核实。

## 架构现状（已验证）

- 7788 = sidecar 对话口（`ccc-agent-sidecar.py`，CCC_AGENT_PORT=7788），与 Hub :7777 共用同一套前端（dialogue 壳标记）
- 对话热链：浏览器/Desktop → 7788 → :4100 loop-router
- 前端 = 17 顶层 JS + 19 组件 + 3 页面，约 8200 行；对话核心 message.js 723 行（流式/取消/错误重试/附件/工具调用/导出/多 tab+搜索+清理）
- A 系列修复（样式、看板拖拽/进度/滚动、聊天错误态重试、登录态）均已在 7788 生效

## 三条线评估

### ① 对话（核心）— 体验中等偏上，缺感知层

已有：流式、取消、错误态+重试、附件、模式/模型切换、斜杠命令、工具调用展示、导出、多项目多 tab + 搜索 + 会话清理。

缺（按影响排序）：
1. 断连感知：sidecar/网络挂掉无横幅，用户以为模型在思考（A 系列暂缓项）
2. 模型档位异常无提示：/health 拉不到或档位为空时静默
3. 流式细节：流式首包慢无感知、流式中切 tab 无提示
4. 窄窗口/移动端适配未验证

### ② 运维 — 信息过载，缺「只看问题」模式

已有：各域渲染、relay 优雅降级、日审 reports 兼容、状态色、卡片化。

缺：
1. 对话壳下数据多一跳（sidecar 代理），15s 轮询弱网体验差
2. 850 行页面一屏铺满，红灯/告警缺聚合视图
3. 写操作（apply/采纳）在对话壳下缺二次确认与权限态提示

### ③ 看板 — 功能齐、交互浅

已有：29 卡渲染、←/→ 移卡、epic 进度自动刷新、滚动保持、隐藏/显示。

缺：
1. 筛选/排序无 UI 入口（A2 只做了透传 + 测试锁，页面没控件）
2. 15s 轮询与移卡竞态（暂缓项）——快速操作会闪回
3. 大卡在对话壳双栏布局下的可读性

## 安全（单独最重要）

- sidecar 代码注释（文件头第 8 行）：「对话口默认 CCC_AGENT_AUTH=0（内网）」；但 `_auth_enforced()`（226 行）注释：「默认强制 Token，仅显式设 0/off/false/open 才关」——**两者矛盾**，实际行为取决于 launchd 环境变量
- 若实际默认关：内网任何人打开 7788 即可用模型额度对话 + 看板/运维，与 App 同权重的入口裸奔
- 开鉴权须同步 Desktop 链路（Desktop 直连 7788，需带 token）

## 优化批次建议

- **第一批（对话壳体验，纯前端、风险低）**：断连横幅、模型档位异常提示、看板筛选/排序 UI、轮询竞态序列化、运维「只看红灯」聚合视图
- **第二批（安全收口）**：核对 launchd 实际值 → 统一鉴权口径 → 开 token → Desktop 联动验证
- **第三批（卫生）**：死代码/样式统一（A 系列暂缓清单）
