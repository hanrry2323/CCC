## 待办项

### §1 — F-1 engine backlog 自动消费（4 项）

- [x] **F1-C2** 🔴 **backlog 不保证 FIFO**
  - `list_tasks("backlog")` 按文件名（=task_id）排序，新 task_id 含日期，字典序不一定晚于旧的 → 新任务被先消费，老任务永久饿死
  - **修法**：按 `created_at` 排序或 FIFO by file mtime
  - **受测**：5 backlog 拆解无遗漏
  - **已修**：`_board_store.py` `list_tasks()` 按 `created_at` 升序排列，缺失时降级到 id 字典序
  - **验证**：tests/e2e/test_f1_backlog_failover.sh Step 4 (FIFO order verified)

- [x] **F1-H1** 🟠 **plans/phases 写无 advisory lock**
  - R-07 已保护 `_apply_phase_status_updates`，但 `product_role` 内部 `plan_file.write_text()` + `phases_file.write_text()` 无 lock
  - F-1 让 engine + 外部 CLI 并发成为常态 → 撕裂风险真实
  - **修法**：product_role 入口 acquire lock，与 R-07 同一锁协议
  - **已修**：`ccc-board.py` product_role 入口 `_acquire_product_lock`（fcntl.flock LOCK_EX + LOCK_NB + 重试 + 30s 超时）
  - **验证**：e2e F-1/F-4 仍通过（lock 不干扰）

- [x] **F1-H2** 🟠 **中途崩溃非原子**
  - `plan_file.write_text` 成功 → `phases_file.write_text` 失败 → task 卡在 backlog（有 plan 无 phases），engine 卡在 Step 2（`plan_file.exists() and phases_file.exists()` 为 False → 跳过），永不走 `product_role` 二刷
  - **修法**：写 phases 成功后才设标记，或走临时文件 rename
  - **已修**：先写 phases（temp → rename），再写 plan（temp → rename）；锁持有期间任一 temp 失败 → 锁释放后再进 product_role 重新生成
  - **验证**：temp 文件清理路径在 finally 块中保证

- [x] **F1-H3** 🟠 **Step 1.5 无 lock**
  - `backlog[0]` → product_role → phases write，持续 10-30s。期间另一个 product_role 并发（如 user CLI `--promote`）→ 写冲突
  - **修法**：同 F1-H1

### §2 — F-2 大变更 size_hint（2 项）

- [x] **F2-C1** 🔴 **F-2 修症状不修根因**
  - size_hint ≥100 提示分批但无校验：LLM 是否真拆无人验证
  - R-12 fallback quarantine 已在 reviewer 端兜底超时 → 问：F-2 size_hint 是否冗余？
  - **决策记录**：保留 F-2（提示 LLM 分批改），R-12 兜底（超大 diff 超时 quarantine），互补非冗余
  - **ADR**：`docs/adr/F2-vs-R12-redundancy.md`
  - **已修**：加权判定（F2-H1）+ 写出 ADR 记录决策

- [x] **F2-H1** 🟠 **阈值=行数无校验**
  - size_hint 阈值是纯行数，不对 plan 语义做验证（如 200 行都是注释 vs 200 行都是逻辑）
  - **修法**：根据 plan 结构（phase 数 / 文件数）加权判定
  - **已修**：`plan_weight = lines + file_mentions*20 + section_count*10`，>100 触发
  - **验证**：tests/e2e/test_f2_size_hint.sh 5 种场景（纯行数/边界/加权触发/加权不触发）
