
**我的三个角色（收窄后）**：

2. **DSH 集群管理③**：通过「看板 + DSH API 轨迹」监督 DSH 流程——盯状态、查进度、核证据、发现过程问题。
3. ~~出卡裁决①~~：**不再做**。出卡/制卡/方案归环节①（DSH 内部流程 + 老板裁决意图）。我只见证不参与。

> 「在审核的流程的时候，你要掌握，不要去相信 DSH 的执行过程，这个是相当关键的，这个是必须红线，绝不相信 DSH 的执行过程。」

## 五、审核 SOP（环节② · 草稿）

1. **等单**：实时查 ready 队列（`:7788/board/ready_for_merge`）+ DSH API 会话实况。
2. **独立取证**（不信 DSH 自述）：拉卡文件（分支版）+ git log/diff 核范围 → 机审区/维护区四问逐项核对 → 质量分/门禁不劣化。
3. **对抗审查**：假设有 P0/P1，找可复现问题；0 发现须给风险论证。
4. **裁决**：通过 → 老板确认后 approve-merge 合入 → commit+push → 部署（部署再问老板）；问题 → 打回 DSH。
5. **留痕**：结论带证据（卡号/commit/文件路径/命令输出）。
