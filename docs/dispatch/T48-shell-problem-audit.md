## 目标

对 HTTP 壳（五视图）与桌面端做全量走查，输出**用户可感知**的问题清单（每条带现象/复现步骤/证据/优先级），供 T50 修复。

## 排查方法（必须执行，不能只读代码）

1. **HTTP 壳**：无头 Chrome 逐视图走查（对话/看板/线路图/运维/控制台）+ 免登录直连 + 连续对话 + 工具调用 + 断线模拟 + 视口缩放（桌面/平板/手机宽度）+ 深/浅主题；收集 console error / 网络错误 / 布局溢出。
2. **桌面端**：本地构建运行（或源码走查 + Swift 测试），走查三栏、设置、看板、任务卡流、对话流、主题、窗口缩放/折叠。
3. **专项维度**：① 状态一致性（看板 vs 右栏卡流 vs 对话内任务状态 vs /board/states）；② 文案（技术串、旧口径、错别字、不一致）；③ 交互断点（点了没反应、hover 无反馈、双击/快捷键失效、按钮禁用态误导）；④ 错误处理（失败无提示、错误串怼用户、无限加载）；⑤ 视觉对齐（双壳色板/圆角/间距不一致、深色模式异常、溢出/裁切）；⑥ 性能（卡顿、轮询过多、内存）；⑦ **左栏/项目会话模型与 Codex/Cursor 对照**（布局、密度、交互是否符合成熟工具习惯）。

## 交付物

1. 问题清单文档：`docs/dispatch/T48-audit-report.md`（或回写区完整列出），每条含：编号/现象（用户视角一句话）/复现步骤/证据（截图路径或日志/console 输出）/影响/优先级 P0-P3/建议修复方向。
2. **不少于 15 条**；P0=用户无法完成任务，P1=明显体验受损，P2=细节瑕疵，P3=可后置。
3. 禁止把「风格偏好」「代码风格」当问题；每条必须是用户可感知或影响正确性/一致性。

## 验收标准

1. 清单 ≥15 条且条条有复现步骤 + 证据；覆盖 7 个专项维度（每维至少 1 条）。
2. 无头 Chrome 走查记录（截图/日志）附在回写区；桌面端走查方式说明。
3. 清单按 P0-P3 分级；Codex 复核后转 T50 修复。
4. 本卡不改代码（只排查输出清单）；push 证据。
