## 目标

将短 chunk 门禁检查从手动脚本升级为自动化：每次入库后自动运行 `verify-k23.sh`，短 chunk 占比 >15% 时告警并阻断入库。

## 红线（先看）

1. **只加门禁，不改入库逻辑**：在入库管道末尾增加门禁检查，不改变入库流程本身。
2. **门禁失败不丢数据**：阻断入库时保留已处理数据，待人工确认后重试。
3. 若本卡含 `## 人工批注`，执行体必须先读批注。

## 范围

- `local/pipeline/`：入库管道末尾增加门禁调用
- `scripts/qa/verify-k23.sh`：如需适配自动化调用
- 不动：`local/auto-collect/`、`local/memory-store/`

## 步骤

1. 进入 `/Users/fan/program/apps/hp`，`git status -sb` 确认工作区干净。
2. 读现有入库管道代码和 `verify-k23.sh`。
3. 在入库管道末尾增加：调用 `verify-k23.sh`，解析 short_pct 值。
4. 若 short_pct > 15%：输出告警日志 + 阻断本次入库（保留已处理数据）。
5. 若 short_pct <= 15%：正常完成入库。
6. commit+push 到卡内分支；卡头改为「已回写」。
7. **停手**：禁止写 `## 机审区` / `## 验收区` / 置「已关闭」。## 机审区` / `## 验收区` / 置「已关闭」。等 2017 机审 → 老板「合入批准」。

## 验收标准

1. 入库后自动运行 `verify-k23.sh`，short_pct 输出可见
2. short_pct > 15% 时入库被阻断（exit 非 0），已处理数据保留
3. short_pct <= 15% 时正常完成入库
4. 探针：`git -C /Users/fan/program/apps/hp status -sb` 只含白名单范围改动
