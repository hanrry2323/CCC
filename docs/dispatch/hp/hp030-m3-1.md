### 1. 实现说明
- 在业务仓设计并落地了五服务并行健康探活程序：`scripts/qa/hp-probes.py`。
- 支持 5 个核心服务：`postgres` (5432), `ollama` (11434), `memory-store` (8082), `mcp-server` (8083), `graph-server` (8089)。
- **进程态**：通过 `ps auxww` 深度匹配服务对应的特定运行命令或关键词，提取 PID 进行状态判定。
- **端口态**：使用原生 TCP socket 进行短连接握手测试，判定端口是否在 LISTENING。
- **真实请求态**：针对不同服务发送真请求获取响应（杜绝端口通但连接死锁的僵尸进程）：
  - `postgres`：利用 `psycopg2` 执行 SQL `SELECT 1;`
  - `ollama`：发起 HTTP GET 请求 `/api/version` 获取版本 JSON
  - `memory-store`：发起 HTTP GET 请求 `/memories?limit=1`
  - `mcp-server` (FastMCP streamable-http)：使用两阶段自适应法，先通过无 ID 报错头部动态提取当前活跃的 `mcp-session-id`，随后携带此会话标识进行真正的 JSON-RPC `initialize` 握手
  - `graph-server`：发起 HTTP GET 请求 `/api/version` 获取服务状态 JSON
- 整合巡检链路：将 `hp-probes.py` 作为核心远程巡检段融入 `local/scripts/cluster-health.sh`。
