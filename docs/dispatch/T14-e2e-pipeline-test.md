## 目标

跑通端到端全链路：造一张真实测试任务卡 → Engine `--once` 扫描派发 → 执行体（mock 或真实）完成并回写 → 卡头状态流转 → board 重新导出 → 三视图与线路图正确反映该任务 → 记录流程证据与暴露问题。

## 红线（先看）

1. 不删除任何文件；不碰旧代码；不碰运行面（不启动常驻服务、不动 2017 旧引擎/产线）。
2. 测试任务卡必须是临时卡（`docs/dispatch/T14-E2E-test-card.md`），完成后保留或按验收意见处理，不得污染真实任务序列。
3. 执行体用 mock 或本机可执行体（不依赖 2017 运行面）；不落密钥；不读写外脑。
4. 验收标准不可自行解释；完成必须提交（真实 commit）；工作树只允许预存 2 个无关改动。

## 步骤

1. 建临时测试任务卡（最小可执行：如「修改 server/README.md 补一行状态说明」），含完整字段与验收标准。
2. 走流程：Engine `--once` → 派发决策（按注册表分类）→ 执行体执行并回写（卡头状态按 §3 更新）→ Engine 收单。
3. board 重新导出：验证该任务出现在三视图（实时/7 天/项目）与线路图正确桶；状态流转 待分派→执行中→已回写 有据可查。
4. 产出流程证据：`docs/e2e-pipeline-evidence.md`——各环节命令/输出/状态流转记录 + 暴露问题清单（含修复建议）。
5. 提交 `chore(e2e):`，回写真实 commit hash。

## 验收标准（Codex 按此验收）

1. 全链路各环节证据完整（发单→派发→执行→回写→看板→线路图），状态流转可追溯。
2. 三视图与线路图正确反映测试任务（board.js 重导出为证）。
3. 暴露问题全部登记（含修复建议），无未登记异常。
4. 未碰运行面/旧代码/外脑；测试卡不污染真实任务序列。
5. 真实提交；工作树仅剩 2 个预存项。
