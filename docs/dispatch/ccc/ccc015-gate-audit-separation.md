# 任务卡 ccc015 · 机械门禁与机审职责分离：编译/测试/lint/范围由门禁裁决，机审定位优化就地闭环（OpenCode 执行）

> 关联：阶段 3 P1 · 执行体：OpenCode · 验收：OpenCode · 状态：待分派 · 派发：engine · 项目：ccc · 日期：2026-08-09

## 目标

把「机械硬卡点」从机审（大模型）环节拆回机械门禁：编译/测试/lint/范围等确定性规则由脚本/CI 按 exit code 裁决，门禁不过即挡（确定性打回，不进机审）；机审大模型只做原则性审查与优化改进，发现可修问题**就地修复后直接通过**，不再因机械问题「打回重派」制造死循环（2026-08-09 老板定稿：开发→机械门禁→验收(优化)→人审 四层）。

## 红线（先看）

1. 只改 `server/engine/` 与 `server/tests/`；不碰运行面、不碰业务仓、不改机审独立审查制度（人审「合入批准」不可省）。
2. 机审独立判断保留：原则性问题（架构/业务意图/红线）仍可「机审：不通过」打回，但**不得**因「pytest 没绿 / 范围越界 / 编译失败」这类机械事实打回——那由门禁裁决。
3. 零硬编码：机器路径/端口/模型名不进代码（沿用现有门禁口径）。
4. 若本卡含 `## 人工批注`，执行体必须先读批注并按批注修订目标/步骤后再执行；批注优先于正文。

## 范围

- 修改：`server/engine/main.py`（门禁扩展 + 机审 prompt 职责重写 + 打回路径分流）、`server/tests/test_engine_*.py`（新增门禁/机审分流用例）。
- 不动：`server/web/`、`server/relay/`、`server/board/`（机审区识别等既有逻辑）、`scripts/`。

## 步骤

1. **机械门禁扩展**：在开发回写收单（`_dispatch_and_collect` 回写校验段）新增确定性门禁层——卡内声明门禁探针（编译/测试/lint/范围，每卡可选，卡未声明则跳过），engine 在 worktree 机械执行、按 exit code 裁决：
   - 门禁失败 → 确定性打回开发（`problems` 带具体失败命令/输出片段），**不拉起机审**；
   - 门禁通过 → 放行进机审。
   - 设计要点：探针命令来源写进卡头/卡内字段（如 `## 门禁` 节），engine 通用解析执行，禁止硬编码具体项目命令；范围越界探针=worktree 相对 `origin/main` 白名单 diff 校验（超出卡「范围」节声明的路径即失败）。
2. **机审 prompt 职责重写**（`server/engine/main.py` 中机审席 prompt）：删除「独立复跑测试/编译裁决」职责表述，改为：
   - 只做原则性 Code Review（实现质量/边界/架构隐患/批注落实）；
   - 发现可修问题 → 在 worktree 就地修复并 commit+push，修完直接通过（进 ready）；
   - 原则性红线问题（范围系统性越界/业务意图违背）→ 「机审：不通过（原因）」打回。
3. **打回路径分流**：机审失败分类中，机械特征（测试/编译/lint 失败、范围越界字面）不再走业务打回；`_run_audit_worker` 中 `_audit_output_indicates_rejection` 判定与 pass 判定同口径（截断到 `pid_pending cmd=` 之后，避免 prompt 字样误判）；落盘/push 等机械失败走既有 infra 冷却续审，不进业务 retry 预算。
4. 回归：`python3 -m pytest server/tests/ -v --tb=short` 全绿；既有 74 用例不回归。
5. commit+push 到卡内分支（勿直推 main）；合入前 `git fetch origin && git rebase origin/main`（减 --close-only）；卡头改为「已回写」。
6. **停手**：禁止写 `## 机审区` / `## 验收区` / 置「已关闭」。等 2017 机审 → 老板「合入批准」。

## 验收标准

1. 新增用例：门禁探针失败（如伪造 `pytest` 退出 1）→ 卡直接打回开发、**不拉起机审**（断言 audit 未派发）。
2. 新增用例：机审输出「测试未跑/编译失败」类机械问题 → 不被判业务打回（断言走 infra/就地修复路径，不进 retry 预算）。
3. 机审 prompt 文本中不再含「复跑测试/复跑编译裁决」表述（断言 prompt 构造函数输出）。
4. 既有测试不回归（`pytest server/tests/` 全绿，数量 ≥ 74）。
5. 零硬编码扫描：`server/engine/` 生产代码无字面量机器路径/端口/模型名。

## 回写要求

卡头状态更新为「已回写」；回写区填：实现说明（门禁层设计 + prompt 重写 diff 摘要）、测试输出（新增用例数 + 全量结果）、push 证据（commit hash）、验收自检对照表。
